Notable changes to `@colorffy/css` and `@colorffy/ui`, newest first. Anything
that needs you to edit your own markup is written up in full in the
[migration guide](/migration) — those entries link there instead of
repeating it.

## 3.0.0

### Added

- **Navbar CSS variables.** `.navbar` reads 25 public variables, from
  `--cffy-navbar-bg-color` and `--cffy-navbar-radius` to the link states
  (`--cffy-navbar-link-hover-color`, `--cffy-navbar-link-active-bg-color`, …). Set them on
  `:root` or on a wrapper to restyle every navbar inside it; `nav-island`,
  `nav-transparent` and the stuck state keep their own values. See
  [Navbar → CSS variables](/colorffy-ui/components/navbar#css-variables).
- **Popover menu CSS variables.** `.popover-menu-container` reads 16
  public variables for the panel (`--cffy-popover-menu-bg-color`, `-radius`,
  `-shadow`, `-min-width`, …) and its items (`--cffy-popover-menu-item-color`,
  `-hover-*`, `-active-*`). Destructive items keep their danger color. See
  [Popover menu → CSS variables](/colorffy-ui/components/popover-menu#css-variables).
- **Menu tools CSS variables.** The `.menu-tools` mega menu reads 13 public
  variables for its panel (`--cffy-menu-tools-bg-color`, `-radius`, `-max-height`,
  …), tabs and links. See
  [App layout](/colorffy-css/layout/app-layout#menu-tools-css-variables).
- **Dropdown CSS variables.** Every dropdown panel reads 17 public variables
  (`--cffy-dropdown-bg-color`, `-radius`, `-min-width`, …) and its items
  (`--cffy-dropdown-item-color`, `-hover-*`, `-active-*`, padding and radius). The
  easing and duration hooks also reach the mobile bottom sheet, whose
  variant no longer repeats the base timing. See
  [Button menu → CSS variables](/colorffy-ui/components/button-menu#css-variables).
- **Dialog CSS variables.** Dialogs read 18 public variables
  (`--cffy-dialog-bg-color`, `-radius`, `-padding`, `-backdrop-color`,
  `-backdrop-blur`, title, subtitle and icon colors, …). The easing and
  duration now reach modals and side sheets: they re-declared the same
  overshoot curve and 600ms over a base easing that never ran, and the side
  sheet repeated the base radius, so those duplicates are gone. See
  [Modal → CSS variables](/colorffy-ui/components/modal#css-variables).
- **Sidebar CSS variables.** The drawer reads 19 public variables
  (`--cffy-sidebar-bg-color`, `-radius`, `-padding`, item colors and their active
  state, the overlay color and blur, …). See
  [Sidebar → CSS variables](/colorffy-ui/components/sidebar#css-variables).
- **Tabs CSS variables.** `UiTabs` reads 14 public variables: the underline
  indicator, the border, tab text and its hover and active states, and
  `--cffy-tabs-pills-*` for pill tabs (container, radius, raised indicator). Pill
  tabs no longer repeat the base active color, so `--cffy-tabs-link-active-color`
  reaches them too. See
  [Tabs → CSS variables](/colorffy-ui/components/tabs#css-variables).
- **Segmented control CSS variables.** `UiSegmentedControls` reads 11 public
  variables for its frame, items and sliding pill. See
  [Segmented controls → CSS variables](/colorffy-ui/components/segmented-controls#css-variables).
- **Footer CSS variables.** `UiFooter` reads 14 public variables for its
  colors, padding, the space above it (now independent of the padding), the
  title, links and icons. See
  [Layout → Footer CSS variables](/colorffy-ui/components/layout#footer-css-variables).
- **Progress, spinner and skeleton CSS variables.** `UiProgressBar` reads
  `--cffy-progress-bg-color`, `-color`, `-label-color`, `-height`, `-radius`,
  `-font-size`, `-easing` and `-duration`; the spinner reads
  `--cffy-progress-spinner-color`; skeletons read `--cffy-skeleton-color` and
  `--cffy-skeleton-radius` (the shimmer follows the color); the shapes loader reads
  `--cffy-loading-shapes-color`. See
  [Progress](/colorffy-ui/components/progress#css-variables) and
  [Skeleton](/colorffy-ui/components/skeleton#css-variables).
- **Alert CSS variables.** Alerts read 24 public variables: colors, radius,
  type, padding and gaps, the title, `--cffy-alert-snackbar-*` / `--cffy-alert-toast-*`
  for snackbars, and `--cffy-pwa-alert-*` for the PWA prompt. Alerts with an icon
  no longer repeat the base gap, so `--cffy-alert-gap` reaches them. See
  [Alert → CSS variables](/colorffy-ui/components/alert#css-variables).
- **Card CSS variables.** Cards read 13 public variables for their surface,
  border, radius, padding, title and text, plus the selected border of
  selectable and link cards. The header and footer corners
  now follow the card radius instead of the compiled `$card-border-radius`.
  See [Card → CSS variables](/colorffy-ui/components/card#css-variables).
- **Button CSS variables.** Buttons read `--cffy-btn-radius`, `-height`,
  `-padding-inline`, `-padding-block`, `-font-size`, `-font-weight`,
  `-icon-size`, `-shadow`, `-easing` and `-duration`, shared by every
  variant; sizes, icon buttons, FABs and `rounded` keep their own values. See
  [Button → CSS variables](/colorffy-ui/components/button#css-variables).
- **Chip CSS variables.** Chips read `--cffy-chip-bg-color`, `-color`,
  `-border-color` and `-radius`; selected chips keep the
  theme's tonal colors. See
  [Chip → CSS variables](/colorffy-ui/components/chip#css-variables).
- **Button group, chip group, FAB group and toggle CSS variables.**
  `--cffy-btn-group-gap`, `--cffy-chip-group-gap`, `--cffy-fab-group-offset-block` /
  `-inline` / `-gap`, and `--cffy-toggle-btn-*` for `UiButtonToggleGroup` (surface,
  border, radius, padding, subtitle and the hover and selected outlines). The
  selected toggle's inset ring now follows its border color. See
  [Button group → CSS variables](/colorffy-ui/components/button-group#css-variables).
- **Badge CSS variables.** Badges read `--cffy-badge-bg-color`, `-color`,
  `-border-color`, `-radius`, `-font-size`, `-font-weight`, `-padding-block`,
  `-padding-inline` and `-icon-size`, and badge groups `--cffy-badge-group-gap`. See
  [Badge → CSS variables](/colorffy-ui/components/badge#css-variables).
- **Accordion CSS variables.** Accordions read 13 public variables for their
  surface, radius (the outer corners of a stacked group), padding, title and
  body text, icons, hover state, motion and the gap between items. See
  [Accordion → CSS variables](/colorffy-ui/components/accordion#css-variables).
- **Avatar CSS variables.** Avatars read 17 public variables for their
  radius, motion, initials tint and text, group overlap and ring, and the
  status dot's size, ring and colors. See
  [Avatar → CSS variables](/colorffy-ui/components/avatar#css-variables).
- **List CSS variables.** Lists read 26 public variables for the item
  surface, text, corners, padding, icon tile, image, active state, trailing
  arrow and motion. See
  [List → CSS variables](/colorffy-ui/components/list#css-variables).
- **Popover CSS variables.** Popovers read 15 public variables for the
  panel surface, border, radius, shadow, size limits, spacing, offset from the
  trigger, header text and motion. See
  [Popover → CSS variables](/colorffy-ui/components/popover#css-variables).
- **Tooltip CSS variables.** Tooltips read `--cffy-tooltip-bg-color`, `-color`,
  `-padding`, `-radius`, `-shadow`, `-font-size`, `-font-weight`,
  `-kbd-bg-color` and `-kbd-color`. See
  [Tooltip → CSS variables](/colorffy-ui/components/tooltip#css-variables).
- **Breadcrumb CSS variables.** Breadcrumbs read 12 public variables for the
  gap, link, hover and current-page colors, the current label's weight and

  [Breadcrumb → CSS variables](/colorffy-ui/components/breadcrumb#css-variables).
- **Stepper CSS variables.** Steppers read 24 public variables for the
  indicator size, corners, text and pending, current and completed colors, the

  [Stepper → CSS variables](/colorffy-ui/components/stepper#css-variables).
- **Timeline CSS variables.** Timelines read 18 public variables for the
  gap, item spacing, connector, dot, icon and image markers, title, text and

  [Timeline → CSS variables](/colorffy-ui/components/timeline#css-variables).
- **Table CSS variables.** `.table` (and `UiDatatable`) reads 20 public

  selected and striped rows, the row hover motion, the sticky-header height and the

  [Datatable → CSS variables](/colorffy-ui/components/datatable#css-variables).
- **Input CSS variables.** Text inputs, textareas, selects and the color

  surface, border, text, placeholder, shadow, hover, focus and invalid states,

- **Checkbox, switch and radio CSS variables.** `.form-check` reads

  [Inputs → Checkbox, switch and radio CSS variables](/colorffy-ui/components/inputs#checkbox-switch-and-radio-css-variables).

  (`--cffy-on-background`), `--cffy-carousel-btn-shadow` (`--cffy-shadow-sm`) and
  `--cffy-carousel-btn-radius` (`--cffy-radius-full`).

  `--cffy-header-*` (spacing, gap, title and description), `UiHeroContent`
  `--cffy-hero-*` (gaps, spacing, line length, description and the actions' offset
  and gap) and `UiSubheadingContent` `--cffy-subheading-gap` and
  `--cffy-subheading-actions-gap`. See
  [Layout → Header CSS variables](/colorffy-ui/components/layout#header-css-variables).
- **Navigation bar CSS variables.** The bottom navigation bar reads
  `--cffy-navigation-bar-bg-color`, `-shadow`, `-item-color`, `-item-active-color`,
  `-item-hover-color`, `-font-size`, `-icon-size`, `-indicator-color`,
  `-indicator-radius`, `-easing` and `-duration`. See
  [Navigation bar → CSS variables](/colorffy-ui/components/navigation-bar#css-variables).
- **Link, code and kbd CSS variables.** Base links read `--cffy-link-color`,
  `-hover-color`, `-active-color`, `-underline-color`, `-easing` and
  `-duration`; `<code>` reads `--cffy-code-color` and `--cffy-code-font-size`; and `<kbd>`
  reads `--cffy-kbd-bg-color`, `-color`, `-font-size`, `-radius` and `-shadow`. See
  [Typography → CSS variables](/colorffy-css/utilities/typography#css-variables).
- **Icon wrap CSS variables.** `.icon-wrap` reads `--cffy-icon-wrap-padding`
  (default `20px`), `--cffy-icon-wrap-radius` (`--cffy-radius-full`),
  `--cffy-icon-wrap-bg-color` (`--cffy-background`), `--cffy-icon-wrap-color`
  (`--cffy-primary-a10`) and `--cffy-icon-wrap-tint-alpha` (`10%`, the strength of
  the colored variants' tint). Sizes keep their own padding and corners, and
  colored variants their own colors.
- **Icon-only tabs.** `UiTabs` takes `iconOnly`: tabs with an `icon` render as
  square icon buttons (`.tabs-icon-only`), with the label kept as visually
  hidden text for screen readers and a native `title` tooltip. See
  [Tabs → Icon-only tabs](/colorffy-ui/components/tabs#icon-only-tabs).
- **State layer tokens.** `--cffy-state-layer-color` (default
  `--cffy-primary-base`), `--cffy-state-hover-opacity` (`8%`) and
  `--cffy-state-pressed-opacity` (`12%`) set the hover and pressed background of
  every interactive surface in one place. See
  [Customization → Hover and pressed states](/colorffy-css/customization#hover-and-pressed-states).
- **Container tokens for tinted surfaces.** For primary, secondary, accent,
  success, warning, danger, info and muted, `--cffy-<color>-container` is the
  tinted surface (a pale tint in light mode, a dark one in dark mode) and
  `--cffy-on-<color>-container` the text and icon color on it, so a custom
  tonal block takes two tokens. Tonal buttons, badges and alerts paint the
  pair; the `.text-*-emphasis` utilities and the active navbar, popover-menu
  and list states read the text token. `--cffy-on-primary-container` existed
  before as plain black or white and was unused; it now carries the primary
  tint. The `.bg-<color>-container` and `.text-on-<color>-container` utilities
  apply them. See [Tonal tokens](/colorffy-css/scss-api/tonal-tokens).

- **`UiButtonMenuItem` `keepOpen`.** Items now close their menu when clicked (see
  Fixed); set `keep-open` on an item that toggles a setting or opens a further
  step so the menu stays put.

- **Container width scale.** `--cffy-container-3xs` (16rem) to `--cffy-container-7xl`
  (80rem) give component widths one t-shirt scale, and `max-w-{size}` utilities
  read the same steps. The sidebar, popovers, popover menu, toasts and dialogs
  take their widths from it, so one token resizes everything on that step. See
  [Customization → Container widths](/colorffy-css/customization#container-widths).

### Changed

- **The sidebar's active-icon color is a public variable.** The leading icon of
  the current-route item read `--_drawer-active-color`, a private variable
  nothing declared. Set `--cffy-sidebar-item-active-icon-color` instead; see
  [Migration](/migration#namespace-the-custom-properties).
- **Small ranges scale their track and thumb.** `size="sm"` on `UiInputRange`
  (`.form-range.form-sm`) used to shrink only the field's height, leaving the
  full-size track and thumb. It now also uses a `0.5rem` track and a
  `1.35rem` × `0.25rem` thumb.
- **One hover and pressed background for every interactive surface.** Each
  component used to pick its own surface token for hover (the card the overlay
  surface, list items and dropdown items `container-high`, tabs and the sidebar
  `container`, table rows `surface-a10`, popover menu items a primary tint),
  so the same gesture looked different from one component to the next and
  barely showed on some surfaces. List items, selectable and link cards,
  accordion headers, dropdown and popover-menu items, tabs, chips, table rows,
  the file dropbox, and sidebar, navbar and menu-tools links now mix their own
  background with the primary color, the same tint the surface ramp is built
  from: 8% on hover, 12% while pressed or focused from the keyboard. Navbar, sidebar, popover-menu and menu-tools
  links gain that pressed state, accordions highlight only while the header
  itself is hovered, disabled list items no longer react to hover, and the
  destructive popover-menu item and a file dropbox holding a valid file use a
  danger or success layer.
- **Tonal ramps mix in `oklab`.** The `a10`–`a90` ramps, the surface ramp, the
  disabled tokens, tonal button, badge and alert backgrounds, and the remaining
  component mixes blended in `srgb`. They now mix in `oklab`, like the state
  layer and text selection, with the percentages retuned so each token keeps
  its lightness: nothing moves more than about 0.03 ΔE in OKLab, and the
  deepest light-mode steps come out a touch darker. Light tonal backgrounds are
  slightly less saturated, since `oklab` doesn't add the extra chroma `srgb`
  picks up when mixing toward white. In dark mode
  `--cffy-tonal-dark-intensity` now defaults to `58%` and
  `--cffy-tonal-light-intensity` to `8%` (were `70%` and `15%`). Overridden
  intensities blend in `oklab` too, so a custom dark-mode value comes out
  darker than before; compare it against the new defaults.
- **Dark-mode tonal ramps darken step by step.** In dark mode the primary,
  secondary and accent ramps darkened from `a10` to `a80` and then jumped back
  to a light tint at `a90`, and the success, warning, danger, info and muted
  ramps mixed toward white from an already light base, so they stayed
  near-white with `a90` landing between `a60` and `a70`. Every ramp now darkens
  from one step to the next in both modes, `a90` included; the light text tone
  it used to hold is `--cffy-on-<color>-container`, which the library now reads
  wherever it read `a90`. Filled semantic buttons darken on hover and press
  instead of lightening, tonal backgrounds and bordered-badge borders come out
  a step deeper, and `--cffy-muted-a10` (secondary text) is slightly dimmer. If
  your own styles read `a90` as a text color, see
  [Migration](/migration#update-tonal-colors).
- **Text on a brand color follows the brand color.** `--cffy-on-<color>` was
  fixed per color (white on primary, secondary, success, danger and info in
  light mode, black in dark mode, always black on accent and warning), so a
  light custom color kept white text unless you overrode it. Each one now
  picks black or white from the lightness of the solid fill the components
  paint, `--cffy-<color>-a10`, whichever has more contrast, in both modes. In
  the default theme, info fills switch to black text (white measured 3.1:1,
  black measures 6.8:1). Values you set yourself still win. Browsers that
  can't evaluate the calculation keep the fixed values: those without
  relative color syntax, and Safari 16.4–17, which implements an older draft
  of it.
- **Tonal buttons step from their container.** Hover and pressed used to lower
  `--cffy-tonal-dark-intensity` by 10% and 20%, so a tonal button ignored any
  surface you set. Each state now mixes the container 15% and 30% back toward
  the fill, which matches the previous colors within ΔE 0.03 and carries an
  overridden `--cffy-<color>-container` through every state. For SCSS users,
  `btn-tonal()` and `container-tonal()` now take the surface instead of
  computing it; see [Migration](/migration#update-tonal-colors).
- **Events drop the `on` prefix.** `UiButton`, `UiButtonMenu` and `UiButtonTooltip`
  emit `click` (with the `MouseEvent`) instead of `onClick`; the inputs emit `update`
  instead of `onUpdate`; `UiModal` and `UiConfirmModal` emit `close` instead of
  `onCloseDialog`; `UiButtonToggleGroup` emits `optionClick` instead of
  `onOptionClick`. Vue adds `on` itself when it builds a listener, so the old names
  had to be written `@on-click`, while a plain `@click` only worked because the
  native click fell through. A disabled or loading button never emits `click`. See
  [Migration](/migration#rename-event-listeners).
- **Sidebar width hook renamed.** `--cffy-nav-drawer-width` is now
  `--cffy-sidebar-width`, named like every other component hook; the default is
  still 18rem. See [Migration](/migration#namespace-the-custom-properties).
- **Dialogs and toasts snap to the container scale.** Their widths moved to the
  nearest step: the confirm dialog tops out at 24rem (was 25rem), `sm` at 28rem
  (was 26rem), `md` at 42rem (was 40rem) and `lg` at 56rem (was 60rem), with
  minimums following the step below; the toast minimum is 18rem (was 300px).
  The sidebar, side sheet, popover and popover menu keep their sizes.
- **Tab and step selection works with `v-model`.** `UiTabs` and `UiSegmentedControls`
  emit `update:activeTab` instead of `updateActiveTab`, and `UiStepper` emits
  `update:activeStep` instead of `updateActiveStep`, so `v-model:active-tab` and
  `v-model:active-step` keep the selection in sync. See
  [Migration](/migration#rename-event-listeners).
- **`id` renders as given.** Buttons, cards, accordions and link tooltips prefixed
  it (`button-save`), and inputs suffixed it on the field (`email-input-text`), so
  the value you passed could not be used for anchors, `<label for>`, scripts or
  tests. The `id` now lands unchanged on the main element. See
  [Migration](/migration#use-the-ids-you-pass).
- **Spacing utilities follow the spacing tokens.** The margin, padding, flow,
  block-spacing, position (`top-*` …), translate and gap utilities compiled
  fixed `rem` values, so changing `--cffy-space-unit` rescaled components but left
  utilities behind. They now read `--cffy-space-*` and `--cffy-space-unit`: same class
  names and the same values at the default unit, no markup changes. `px` stays a
  1px hairline.
- **Empty-state and loading titles use the paired line-height.**
  `UiEmpty`, `UiLoading`, `UiShapeLoading` and `UiExpressiveLoading` titles
  moved from the legacy font-size classes to the t-shirt ones, which pair each
  size with its line-height, so a 20px title's line box grows from 20–24px to
  28px. Icons keep their tight line box.
- **`UiSidebar`'s `header`, `body` and `footer` slots render their regions.**
  They used to place content inside `.drawer-content` without a wrapper, so
  they only worked when filled with the region components. Like `UiCard` and
  `UiModal`, each slot now renders inside its own `.drawer-header` /
  `.drawer-body` / `.drawer-footer`, skipped when empty, with
  `headerClass` / `bodyClass` / `footerClass` for extra classes.
- **Private variables are named after their hooks.** Every `--_*` variable
  fed by a public hook now carries that hook's name (`--_card-gutter-x` →
  `--_card-padding-inline`, `--_nav-tabs-link-color` → `--_tabs-link-color`,
  `--_drawer-*` → `--_sidebar-*`, `--_form-*` → `--_input-*`), and the
  `--_color-pickerp-width` typo is fixed. Rendering is unchanged. Private
  variables were never public API, but if your CSS overrode one, set its
  public hook instead; see
  [Migration](/migration#namespace-the-custom-properties). `UiDatatable`'s
  `stickyHeight` now sets the public `--cffy-table-sticky-max-height`.
- **Every public custom property is namespaced with `--cffy-`.** Unprefixed
  names like `--space-*` and `--theme-*` could collide with other libraries on
  the same page. The semantic `--theme-*` tokens now use the namespace in
  place of `theme-` (`--theme-primary-a10` → `--cffy-primary-a10`), and every
  other public token, component variable, animated `@property` and internal
  anchor name gains it (`--space-16` → `--cffy-space-16`, `--card-bg-color` →
  `--cffy-card-bg-color`). Private `--_*` variables and PrimeVue's `--p-*`
  tokens are unchanged, and the unused `$property-prefix` SCSS variable is
  gone. See the [migration guide](/migration#namespace-the-custom-properties)
  for the find-and-replace.

### Removed

- **`--cffy-on-primary-inverse`, `--cffy-on-secondary-inverse` and
  `--cffy-on-accent-inverse`.** They held the same value as
  `--cffy-on-background` and nothing in the library read them. See
  [Migration](/migration#update-tonal-colors).
- **Legacy font-size tokens and classes.** The ordinal `--fs-100` … `--fs-600`,
  `--fs-sm-100` … `--fs-sm-500` and `--fs-xl-100` tokens and their `.fs-*`
  classes, deprecated since 2.5, are gone. Use the t-shirt scale (`--cffy-fs-4xs` …
  `--cffy-fs-5xl`, `.fs-base`, …); the t-shirt classes also set the paired
  line-height. See the
  [rename table](/migration#clear-the-2x-deprecations).
- **Deprecated SCSS variables.** `$space-1` / `$space-2` / `$space-3` (use
  `var(--cffy-space-16/32/48)`) and the color and font variables deprecated in 2.8
  (`$primary`, `$secondary`, `$accent`, `$success`, `$warning`, `$danger`,
  `$info`, `$muted`, `$primary-colors`, `$font-*`) are gone. Nothing read them;
  a `@forward … with (…)` that still sets one now fails to compile, so drop it
  and set the `--cffy-color-brand-*` / `--cffy-font-*` tokens instead. See
  [Migration](/migration#clear-the-2x-deprecations).
- **`ISegmentedTab.position`.** Ignored since the segmented pill started
  reading the active tab's real geometry; the field is gone and
  `ISegmentedTab` is now an alias of `ITabItem`. Delete `position` from your
  items.
- **`UiPopoverMenu`'s identity props and `body-extra` slot.** `user`,
  `avatarUrl`, `avatarCustomClass` and `subtitle` rendered nothing since the
  header became a title plus the close button; put the identity in the `header`
  slot with `UiPopoverMenuUser`. `body-extra` is gone too: to add rows to a
  `menuItems` menu, render the body yourself in `#body`. See the

- **`UiInputFile`'s `large` prop.** Use `size="lg"`, which every input
  shares, for the taller dropbox.
- **`BaseSkeleton`'s `isThumbnail` prop.** Use `variant="thumbnail"`.
- **`UiEmpty`'s `#button` slot.** The legacy fallback inside `#action` is
  gone; rename the slot to `#action`.
- **`UiSidebarHeader`, `UiSidebarBody` and `UiSidebarFooter`, and the default
  slots of `UiSidebar` and `UiPopoverMenu`.** Panel components now take their
  regions through named slots only. Move sidebar regions into `#header`,
  `#body` and `#footer`, and a menu's default-slot content into `#body`. See the
  [migration guide](/migration#replace-removed-props-slots-and-components).

### Fixed

- **List items animate their background and border.** The item transition had
  no duration, so hover, pressed and active changes snapped. They now ease over
  `--cffy-duration-200`.
- **`UiExpressiveLoading` title sizes were inverted.** `size="sm"` used the
  legacy `fs-500` (20px), the default `fs-600` (16px), and `lg` a `fs-700` class
  that never existed, so it fell back to 15px: the larger the size, the smaller
  the title. They are now 16px, 20px and 24px.
- **`UiGridSkeleton` previews have their height again.** Each card set
  `--fixed-size: 6.25rem`, but the `.h-fixed` utility reads `--cffy-h-fixed`, so the
  preview block fell back to its 2.5rem minimum. It now sets `--cffy-h-fixed`.
- **Popover menu items no longer restyle what you put in them.** The item
  colored and resized every `<p>` and `<i>` inside it, so buttons placed in the
  `trailing` slot (a theme switcher, say) lost their own text and icon colors.
  The rules now apply only to the item's label, leading icon and trailing icon.
- **`UiButtonMenuItem` closes its menu.** Clicking an item left the dropdown open
  until you clicked elsewhere, and items inside a submenu left both levels open.
  A click now closes the whole menu.
- **`UiModal` renders `title` and `message`.** Both props were declared and
  documented but never shown. They now fill the header and body when those slots
  are empty. Clicks outside a closed modal also stopped emitting a close event:
  the outside-click listener ran whether or not the dialog was open.
- **`UiConfirmModal` shows `loadingLabel` and emits `close`.** The confirm
  button kept its label while loading, and the documented close event was never
  emitted. Both now work, and outside clicks are ignored while it is closed.
- **`UiCard` no longer shows its title as a browser tooltip.** The `title` prop was
  also bound to the root's native `title` attribute. The card body also stopped
  re-applying the card color, so a text utility on the card (`text-on-primary`)
  now reaches the body.
- **`UiAvatar` shows the photo when both `src` and `initials` are set.** Initials
  took priority, so the image never appeared. They are now the fallback for a
  missing or broken image, as documented.
- **`UiButtonTooltip` links.** `to`, `href`, `as` and `type` were accepted but not
  passed to the button, so a tooltip button couldn't navigate.
- **`UiSegmentedControls` renders tab icons and badges.** Its tabs accept `icon` and
  `badge` like `UiTabs`, but only the label was drawn.
- **`UiBadge` renders a `<span>`.** The `<div>` root made badges invalid inside
  paragraphs and buttons (tabs, menu items), which broke SSR hydration when a badge
  sat in a `<p>`.
- **`UiTimeline` styles the `neutral` variant.** It was accepted but had no marker
  colors; it now uses the muted container pair.
- **`UiLinkTooltip` honors `placement`.** The prop was declared but never passed to
  the tooltip.
- **`UiInputSelect` placeholder is in English.** The default was
  "Clic para seleccionar"; it is now "Select an option".
- **`UiNavbarNav` `position` aligns as documented.** From 992px, `start` pushed its
  group away from the brand (`margin-left: auto`) and `end` pushed away from the
  far edge (`margin-right: auto`), so a start and an end group floated toward the
  middle with a gap after the last item. `start` now sits next to the brand and
  `end` against the far edge. If you used two `start` groups to push everything
  to the right, make the right-hand group `end`.
- **Prefixed and suffixed inputs line up.** An input with a prefix or suffix nests
  an `.input-group` inside its `.form-group`, and both added the bottom margin, so
  the field took twice the spacing. Inside a navbar item the form margin is now
  dropped entirely, and the prefix and suffix follow `variant="transparent"` (no
  border or background) and `rounded` (full radius) instead of keeping the default
  boxed look.
- **`.grid-main-content` no longer scrolls sideways.** Its content column was
  `1fr`, which cannot shrink below the widest thing inside it, so a wide table
  pushed the whole page past the viewport instead of scrolling in its own
  `.table-responsive`. The column is now `minmax(0, 1fr)`.
- **Alert actions stay beside the text.** An alert with a title switched to a
  single column, which pushed its actions onto a row of their own at the bottom.
  Actions now sit next to the content and only drop below it when the alert is
  450px wide or less.
- **The segmented control indicator moves without lagging.** The labels
  transitioned `font-weight`, so with a proportional font the active label kept
  growing while the indicator travelled toward it, and the indicator trailed
  behind a moving target. The weight now changes at once.
- **`UiEmpty` centers its action.** Buttons in the `action` slot sat at the left
  edge because they are block-level; the slot is now wrapped in a centered
  `UiButtonGroup`, which also spaces several actions.
- **List item actions keep their width.** The item content took `width: 100%`,
  so the `list-action` slot was squeezed until its button labels wrapped. The
  content now takes the free space and the actions keep their natural width.
- **The sidebar rail centers its header.** The rail nudged an image or icon logo
  with a fixed 1rem offset and left anything else at the start edge. The header
  now centers whatever logo it holds.
- **`UiShapeLoading` subtitle is readable.** It carried `text-muted`, which overrode
  the label color meant for text on the blob, so the subtitle faded into the shape.
  It now uses the same color as the title, and both lines are centered on the
  shape (a shorter subtitle used to sit at the left edge).
- **`<kbd>` keeps its light-mode background in older browsers.**
  `--cffy-surface-kbd` called `color-mix()` without an interpolation space,
  which only browsers supporting the newer optional-space syntax accept, so
  elsewhere the token was invalid and the key rendered unpainted. It now names
  `oklab`, the space those browsers default to, so they render it the same.

## 2.7.0

### Added

- **`UiTabs` takes `fit` and `rounded`.** `fit` makes the tab bar only as wide
  as its tabs instead of spanning its container (ignored with `fluid`).
  `rounded` makes pill tabs and their indicator fully rounded; it only applies
  with `pillTabs`. Both radii come from one private variable,
  `--_nav-tabs-item-radius`.
- **`UiAvatar` and `UiAvatarGroup` take a `color` prop.** It tints initials and
  placeholder avatars with any theme color, at the color's fixed tone and 25%
  opacity, in place of adding a `bg-*-fixed` class. On the group it applies to
  every avatar and the "+N" overflow avatar, and `avatars` entries can override
  it. The CSS classes are `.avatar-{color}`, driven by `--_initials-base-color`
  and `--_initials-alpha`.
- **`UiAvatar` and `UiAvatarGroup` take a `variant` prop.** `transparent` is
  the see-through tint, `tonal` the same tint made opaque, and `filled` the
  full theme color with its on-color text (`.avatar-tonal`, `.avatar-filled`).
  `UiAvatar` defaults to `transparent`; `UiAvatarGroup` defaults to `tonal`.
- **`border-neutral`, `border-black` and `border-opacity-*`.** `border-neutral`
  uses the body text color, so it flips with dark mode; `border-black` matches
  `text-black`. `border-opacity-{0…100}` fades any border color toward
  transparent with `color-mix()` in `oklab`.
- **Shape, weight, motion and focus tokens.** `--radius-*`,
  `--border-width-sm` / `-md`, `--fw-400…800`, `--ease-*` and
  `--focus-ring-color` / `--focus-ring-offset` are CSS custom properties on
  `:root`, and every component reads them. Override them at runtime without
  recompiling; the SCSS variables still set their defaults. See
  [customization](/colorffy-css/customization).

### Changed

- **Avatars in a `UiAvatarGroup` are opaque.** Initials and the "+N" overflow
  avatar used a 25% transparent background, so the image they overlap showed
  through. The group now defaults to `variant="tonal"`, the same tint made
  opaque; pass `variant="transparent"` for the previous look.
- **Easing curves no longer have `cubic-bezier()` fallbacks.** `linear()` is
  supported in every current browser, so the 25 `@supports` blocks that swapped
  them in are gone and each component declares its curve once. Browsers
  without `linear()` support (before Chrome 113, Firefox 112 and Safari 17.2)
  now skip those transitions instead of using a simpler curve.
- **Reduced motion calms the overshooting curves.** Under
  `prefers-reduced-motion: reduce`, `--ease-spring`, `--ease-overshoot-soft` and
  `--ease-bounce` resolve to `--ease-decelerate`, so dialogs, dropdowns,
  avatars and the rest of the components using them settle without overshooting
  or bouncing.
- **Font sizes are in `rem`, not `px`.** The 17 remaining pixel font sizes
  (body text, buttons, tables, tooltips, badges, icons) render the same at the
  default browser size and now follow the user's font-size setting. If your
  site changes the root font size (e.g. `html { font-size: 62.5% }`), these
  now scale with it like the spacing and `--fs-*` tokens already did: body
  text set to `.875rem` renders at 8.75px with a 10px root.
- **Full-height layouts use `dvh`.** The sidebar, dialogs, the PrimeVue dialog
  and `.pane-content` size themselves with dynamic viewport units, so mobile
  browser toolbars no longer push them past the visible area. The `.vh-*`
  utilities keep `vh`.
- **`--fs-xs` no longer shrinks below `--fs-2xs`.** Its minimum was `0.60rem`,
  smaller than `--fs-3xs` and `--fs-2xs`, so on narrow screens "xs" text
  rendered smaller than the steps below it. The minimum is now `0.75rem`.
- **`border-white` and `border-dark` use the brand color tokens**
  (`--color-brand-white-500`, `--color-brand-dark-500`), like `text-white` and
  `text-dark`, instead of compiled SCSS colors.

### Fixed

- **Focused inputs are visible in forced-colors mode.** Form controls drew
  their focus ring with `box-shadow` and removed the outline; forced-colors
  mode (Windows High Contrast) drops box-shadows, so focus disappeared. They
  now add a `Highlight` outline under `@media (forced-colors: active)`.
- **The progress bar transition always has a duration.**
  `--_progress-easing-duration` was only declared inside the `linear()`
  `@supports` block; it is now part of `.progress`'s defaults.
- **`border-animated` glows without a gradient preset.** Its glow is a
  `conic-gradient()` of `--_border-gradient`, which only the `gradient-{name}`
  classes set, so on its own the gradient was invalid, the background was
  dropped and nothing showed. It now defaults to the same primary gradient as
  `border-gradient`.
- **`border-animated` stops spinning under reduced motion.** Its `::before` and
  `::after` ran `angle-spin` with no `prefers-reduced-motion` check, unlike
  `border-gradient-spin`. Under `prefers-reduced-motion: reduce` the animation
  is now `none`, so the glow stays still at its starting angle.

### Added

  `gutter` prop for the space below it, and an `#actions` slot for a badge or
  control beside it.

### Changed

- **`.text-subheading` uses the type tokens.** It picks up
  `--fs-lg--line-height` and the `--space-*` gutters, and no longer runs the
  `text-variable` mixin: it sets `--font-primary` directly, which every font
  honours.
- **Chips split the container from the selected color.** `.btn-chip` is the
  outline container and `.chip-elevated` the raised one; the color classes
  (`.chip-primary`, `.chip-secondary`, `.chip-neutral`) only apply together with
  `.chip-active`. `.a40` and `.a60` are removed, and `.chip-active` no longer
  forces a pill radius. See
  [the migration note](/migration#chips-split-the-container-from-the-selected-color).

- **`UiHeaderContent` renamed `hideActionsOnMobile` to `hideActionsWhenNarrow`,
  defaulting to `false`.** The old name described a device, but the mechanism is
  a container query: a narrow header collapses inside a wide window too. The old
  default also destroyed the page's primary actions below 700px unless you opted
  out, so hiding them is now something you opt in to; otherwise they wrap below
  the title.
- **`UiHeaderContent` emits `back` instead of `click`.** Declaring `click` as an
  emit meant a consumer's `@click` never attached as a native listener — it
  fired only for the back button. `@click` now behaves like any other native
  listener, and `@back` carries the intent.
- **`UiHeaderContent`'s `containerClass` accepts `ClassValue`.** It previously
  took `string | string[]` and stringified the object form to `[object Object]`.
  Existing values keep working.

- **`UiPaneContent`'s `customClass` and `containerClass` accept `ClassValue`.**
  Same widening as `UiHeaderContent`; existing values keep working.
- **The page header's back-navigation class is `.page-header-back`.** It was
  `.page-header-breadcrumb`, which described a component the header does not
  render. The back button is also centred against the title block now, instead
  of aligning to its top edge.
- **The header's bottom margin moved to `.header-container` and has its own
  token.** `--_header-block-end` and `--_header-back-gap` split out of
  `--_header-columns-gap`, which was setting the title/actions gap and the space
  below the header at once. The margin sat on the inner `.header`, so a padded
  or tinted container trapped it inside its own box and a `mb-*` utility on the
  container stacked on top of it. On the container it is a single margin that
  utilities override, since `utilities` is layered after `components`.

- **`UiHeaderContent` takes an `as` prop.** The title was always an `h1`, so a
  page using the component for its section headers emitted several. It defaults
  to `h1`; pass `as="h2"` and below for sections.
- **`UiHeaderContent` takes a `headline` prop.** It renders a small eyebrow
  label above the title with `caption text-primary`.
- **`UiHeaderContent` takes a `size` prop.** `sm` (the default, `--fs-xl`)
  through `2xl` (`--fs-5xl`), each step also applying the line height the type
  scale pairs with it. `UiHeroContent` uses the same `sm`–`xl` vocabulary on the
  display scale, so one size language covers both.
- **The header title no longer uses the `text-variable` mixin, and its 992px
  breakpoint is gone.** The mixin pinned the title to `wght`/`GRAD`/`wdth`
  variation axes that most families do not ship, and swapped the typeface behind
  an `@supports` test; `$type-h1` already gives the `h1` the same family and
  weight in a way every font honours. The breakpoint then swapped `--fs-xl` for
  `--fs-lg`, but the `--fs-*` scale is already fluid, so the title shrank twice
  and landed at 16px on a phone. It now scales once, 20px to 24px.

- **`UiHeaderContent` and `UiHeroContent` take a `viewTransitionName` prop.**
  The header hard-coded `view-transition-name: selected-header` on every title
  and `selected-description` on every description. A name has to be unique per
  document, so a page with more than one header — a page title plus its section
  headers — made the browser skip the transition entirely rather than run it.
  The name is also the key pairing two pages, which only the app knows, so it
  is now passed in and nothing is emitted without it. `contain: paint` and the
  `fit-content` inline size come with it instead of applying to every header.

- **The footer's gradient underlay, hover radius and rounded top corners, and
  `.dialog-highlight`.** Both drew a gradient through a pseudo-element; the
  footer also squared its top corners on hover, and its corners are now flat
  with no radius transition left to animate.
- **`.footer-row` declares its own direction.** It set a custom property the
  base rule never read, so a row group was horizontal only because that is the
  flex default. A row group with a title now keeps the heading on its own line
  instead of inline with the links.

- **Card surfaces are static and interaction is its own class.**
  `.card-outline`, `.card-pane` and `.card-elevated` now only describe the
  surface; `.card-selectable` and `.card-link` carry every hover, press and
  focus state, including the elevated card's `sm` → `md` → `lg` shadow
  escalation. A plain elevated card previously animated its shadow with nothing
  clickable behind it. `.card-link` also picks up the same background feedback
  as a selectable card, which it had diverged from. See
  [the migration note](/migration#card-surfaces-are-static-and-interaction-is-its-own-class).
- **The selectable card keeps its variant's border and its own radius.** It set
  a 2px transparent border to reserve room for the selected ring; with
  `box-sizing: border-box` the outer box never moved anyway, so the ring is a
  1px border that matches a static `.card-outline` beside it. The selected and
  pressed states also hard-coded `$rounded-lg` / `$rounded-xl`, which ignored a
  configured `$card-border-radius` — on a 4px theme, clicking a card ran it
  4px → 25px → 12px and left it there. The radius no longer changes.
- **The selectable card's ring answers `:focus-visible`.** It was `:focus`, so

- **The selectable card's hover lift is 4px.** It was 8px, which read as a
  drag rather than a hover; `card-sm` steps down to 2px alongside it.

### Removed

- **`UiHeaderContent`'s `actions` prop.** Filling the `#actions` slot is the
  signal; passing the slot without the flag used to render nothing, silently.
- **`.subheading-m2`.** It set the same gutter `.text-subheading` already
  defaults to, so it never changed anything, and the reference documented it as
  a "large margin" it could not produce. `subheading-m1` and `subheading-m0`
  stay for a tighter gutter or none.
- **`@colorffy/ui`'s `./style.css` export.** The package no longer emits a
  stylesheet: its one scoped style block moved into `@colorffy/css`, which every
  consumer already loads. Nothing referenced the export, and it now pointed at a
  file that is not built.
- **`.page-header-featured` and the header's `.col-heading` / `.col-actions`
  rules.** None of them had any markup behind them: the featured badge block
  styled a composition no component rendered, and the two media queries targeted
  classes that exist nowhere. The back-navigation and actions layouts are
  unaffected.

### Fixed

- **`subheading-m0` / `m1` now move the space below the block.** The modifiers
  set `--_text-subheading-gutter` on the heading, and a custom property never
  reaches a sibling, so the description below kept its default margin whichever
  modifier was applied. Each modifier now also sets the description's margin.
- **The title-to-description gap no longer follows the gutter.** It was half the
  gutter, so tightening the space below the block squeezed the title against its
  own description — 2px at `subheading-m1`. It is now its own
  `--_text-subheading-gap`, fixed at `--space-8`.
- **`.card-selectable` no longer erases the variant's border.**
  `.card-outline.card-selectable` and `.card-frosted.card-selectable` matched at
  the same specificity, and `.card-selectable` came last in the file, so its
  `--_card-border-color: transparent` won and the card rendered with no outline
  at all until it was pressed or selected. It no longer declares the colour at
  rest, which the base `.card` already defaults to transparent.
- **An interactive card's transitions all run.** `.card-selectable` and
  `.card-link` each declared their own `transition`, so on a card that was both
  — which `UiCard` produces whenever `selectable` meets `to`/`href` — the
  later rule won and the lift and the ring never animated. `box-shadow` was also
  missing from the selectable list, so an elevated card jumped straight to its
  hover shadow. One shared declaration now covers every interactive card.
  `--_card-easing-in` also has its non-`linear()` fallback back: it was only
  defined inside the `@supports` block, and an undefined custom property in a
  `transition` makes the whole declaration invalid at computed-value time, so
  without `linear()` support the card had no transition at all.
- **A `card-pane` card gives hover feedback in light mode.** The shared hover
  steps the background to `--theme-surface-overlay`, which resolves to the same
  white as the pane's own surface in a light theme — an interactive pane card
  changed nothing under the pointer. Pane now steps to `--theme-surface-a30`,
  which contrasts in both schemes, and carries its own press step so `:active`
  is not outranked by it.

#### The page header title scales down again

`.header` stepped its title down to `--fs-lg` below 992px through
`:where(.col-heading h1:is(.text-title))` — a selector that matched nothing, and
whose `:where()` wrapper would have given it zero specificity even if it had.
The size now flows through `--_header-title-size`, overridden inside the
`.header` rule itself, so it carries the same specificity as the value it
replaces.

#### The header's view transitions actually apply

`view-transition-name`, `contain: paint` and the `fit-content` inline size for
`.text-title` / `.text-description` lived in a Vue scoped style block that
compiled to `@colorffy/ui`'s `dist/ui.css` — a file nothing imported, so the
declarations never reached the page. They now live here in `_header.scss`
alongside the rest of the header rules.

#### Connected groups no longer flatten their inner corners

The rounded end of `.btn-group-connected` came from a fixed
`--_btn-connected-radius: 50px`. On a 32px-tall button that is 50px + 50px down
one side against a 32px box, and the spec answer to radii that overflow a side
is to scale **every corner of that element** by the same factor — here
`32 / 100`. The first button's inner corners, asking for the 4px of
`--_btn-radius`, rendered at 1.3px and read as square next to their siblings:

```
before   first: 50, 1.3, 1.3, 50   middle: 4, 4, 4, 4
after    first: 16, 4,   4,   16   middle: 4, 4, 4, 4
```

The radius is now derived from the button instead of hard-coded:

```scss
.btn-group-connected .btn {
  --_btn-connected-radius: calc(var(--_btn-height) / 2);
}
```

The two radii on a side then sum to exactly `--_btn-height`, which `min-height`
guarantees is never taller than the button, so the scale factor stays 1 and the
inner corners keep their own value. It also tracks the size variants — `btn-sm`,
`btn-lg` and `btn-icon` each get the pill that fits them.

::note
If you set `--_btn-connected-radius` yourself, move it onto the buttons
(`.btn-group-connected .btn`) — a declaration on the group is now shadowed by
the one above.
::

#### Vertical connected groups follow the button radius

`.btn-group-vertical.btn-group-connected` had three separate mismatches: middle
buttons were pinned to `$button-border-radius` instead of `--_btn-radius`, so a
group of `btn-sm` got 8px corners where the horizontal variant gave 4px; the
first and last button squared their inner corners to `0`, although the group is
separated by a gap; and the joined variant set `border-radius: 0` as a shorthand
that outranked the end rules, so vertical joined groups lost their pill ends
entirely. All three now behave like the horizontal variant.
