Notable changes to `@colorffy/css` and `@colorffy/ui`, newest first. Anything
that needs you to edit your own markup is written up in full in the
[migration guide](/migration) — those entries link there instead of
repeating it.

## 3.0.0

### Added

- **Navbar CSS variables.** `.navbar` reads 26 public variables, from
  `--navbar-bg-color` and `--navbar-radius` to the link states
  (`--navbar-link-hover-color`, `--navbar-link-active-bg-color`, …). Set them on
  `:root` or on a wrapper to restyle every navbar inside it; `nav-island`,
  `nav-transparent` and the stuck state keep their own values. See
  [Navbar → CSS variables](/colorffy-ui/components/navbar#css-variables).
- **Popover menu CSS variables.** `.popover-menu-container` reads 17
  public variables for the panel (`--popover-menu-bg-color`, `-radius`,
  `-shadow`, `-min-width`, …) and its items (`--popover-menu-item-color`,
  `-hover-*`, `-active-*`). Destructive items keep their danger color. See
  [Popover menu → CSS variables](/colorffy-ui/components/popover-menu#css-variables).
- **Menu tools CSS variables.** The `.menu-tools` mega menu reads 15 public
  variables for its panel (`--menu-tools-bg-color`, `-radius`, `-max-height`,
  …), tabs and links. See
  [App layout](/colorffy-css/layout/app-layout#menu-tools-css-variables).
- **Dropdown CSS variables.** Every dropdown panel reads 18 public variables
  (`--dropdown-bg-color`, `-radius`, `-min-width`, …) and its items
  (`--dropdown-item-color`, `-hover-*`, `-active-*`, padding and radius). The
  easing and duration hooks also reach the mobile bottom sheet, whose
  variant no longer repeats the base timing. See
  [Button menu → CSS variables](/colorffy-ui/components/button-menu#css-variables).
- **Dialog CSS variables.** Dialogs read 18 public variables
  (`--dialog-bg-color`, `-radius`, `-padding`, `-backdrop-color`,
  `-backdrop-blur`, title, subtitle and icon colors, …). The easing and
  duration now reach modals and side sheets: they re-declared the same
  overshoot curve and 600ms over a base easing that never ran, and the side
  sheet repeated the base radius, so those duplicates are gone. See
  [Modal → CSS variables](/colorffy-ui/components/modal#css-variables).
- **Sidebar CSS variables.** The drawer reads 20 public variables
  (`--sidebar-bg-color`, `-radius`, `-padding`, item colors and their hover
  and active states, the overlay color and blur, …). See
  [Sidebar → CSS variables](/colorffy-ui/components/sidebar#css-variables).
- **Tabs CSS variables.** `UiTabs` reads 15 public variables: the underline
  indicator, the border, tab text and its hover and active states, and
  `--tabs-pills-*` for pill tabs (container, radius, raised indicator). Pill
  tabs no longer repeat the base active color, so `--tabs-link-active-color`
  reaches them too. See
  [Tabs → CSS variables](/colorffy-ui/components/tabs#css-variables).
- **Segmented control CSS variables.** `UiSegmentedControls` reads 11 public
  variables for its frame, items and sliding pill. See
  [Segmented controls → CSS variables](/colorffy-ui/components/segmented-controls#css-variables).
- **Footer CSS variables.** `UiFooter` reads 14 public variables for its
  colors, padding, the space above it (now independent of the padding), the
  title, links and icons. See
  [Layout → Footer CSS variables](/colorffy-ui/components/layout#footer-css-variables).
- **Progress, spinner and skeleton CSS variables.** `UiProgressBar` reads
  `--progress-bg-color`, `-color`, `-label-color`, `-height`, `-radius`,
  `-font-size`, `-easing` and `-duration`; the spinner reads
  `--progress-spinner-color`; skeletons read `--skeleton-color` and
  `--skeleton-radius` (the shimmer follows the color); the shapes loader reads
  `--loading-shapes-color`. See
  [Progress](/colorffy-ui/components/progress#css-variables) and
  [Skeleton](/colorffy-ui/components/skeleton#css-variables).
- **Alert CSS variables.** Alerts read 24 public variables: colors, radius,
  type, padding and gaps, the title, `--alert-snackbar-*` / `--alert-toast-*`
  for snackbars, and `--pwa-alert-*` for the PWA prompt. Alerts with an icon
  no longer repeat the base gap, so `--alert-gap` reaches them. See
  [Alert → CSS variables](/colorffy-ui/components/alert#css-variables).
- **Card CSS variables.** Cards read 14 public variables for their surface,
  border, radius, padding, title and text, plus the hover background and
  selected border of selectable and link cards. The header and footer corners
  now follow the card radius instead of the compiled `$card-border-radius`.
  See [Card → CSS variables](/colorffy-ui/components/card#css-variables).
- **Button CSS variables.** Buttons read `--btn-radius`, `-height`,
  `-padding-inline`, `-padding-block`, `-font-size`, `-font-weight`,
  `-icon-size`, `-shadow`, `-easing` and `-duration`, shared by every
  variant; sizes, icon buttons, FABs and `rounded` keep their own values. See
  [Button → CSS variables](/colorffy-ui/components/button#css-variables).
- **Chip CSS variables.** Chips read `--chip-bg-color`, `-color`,
  `-border-color`, `-radius` and `-hover-bg-color`; selected chips keep the
  theme's tonal colors. See
  [Chip → CSS variables](/colorffy-ui/components/chip#css-variables).
- **Button group, chip group, FAB group and toggle CSS variables.**
  `--btn-group-gap`, `--chip-group-gap`, `--fab-group-offset-block` /
  `-inline` / `-gap`, and `--toggle-btn-*` for `UiButtonToggleGroup` (surface,
  border, radius, padding, subtitle and the hover and selected outlines). The
  selected toggle's inset ring now follows its border color. See
  [Button group → CSS variables](/colorffy-ui/components/button-group#css-variables).
- **Badge CSS variables.** Badges read `--badge-bg-color`, `-color`,
  `-border-color`, `-radius`, `-font-size`, `-font-weight`, `-padding-block`,
  `-padding-inline` and `-icon-size`, and badge groups `--badge-group-gap`. See
  [Badge → CSS variables](/colorffy-ui/components/badge#css-variables).
- **Accordion CSS variables.** Accordions read 14 public variables for their
  surface, radius (the outer corners of a stacked group), padding, title and
  body text, icons, hover state, motion and the gap between items. See
  [Accordion → CSS variables](/colorffy-ui/components/accordion#css-variables).
- **Avatar CSS variables.** Avatars read 17 public variables for their
  radius, motion, initials tint and text, group overlap and ring, and the
  status dot's size, ring and colors. See
  [Avatar → CSS variables](/colorffy-ui/components/avatar#css-variables).
- **List CSS variables.** Lists read 28 public variables for the item
  surface, text, corners, padding, icon tile, image, hover, pressed and active
  states, trailing arrow and motion. See
  [List → CSS variables](/colorffy-ui/components/list#css-variables).
- **Popover CSS variables.** Popovers read 15 public variables for the
  panel surface, border, radius, shadow, size limits, spacing, offset from the
  trigger, header text and motion. See
  [Popover → CSS variables](/colorffy-ui/components/popover#css-variables).
- **Tooltip CSS variables.** Tooltips read `--tooltip-bg-color`, `-color`,
  `-padding`, `-radius`, `-shadow`, `-font-size`, `-font-weight`,
  `-kbd-bg-color` and `-kbd-color`. See
  [Tooltip → CSS variables](/colorffy-ui/components/tooltip#css-variables).
- **Breadcrumb CSS variables.** Breadcrumbs read 12 public variables for the
  gap, link, hover and current-page colors, the current label's weight and
  maximum width, separators, text and icon size, and motion. Icon separators
  now follow `--breadcrumb-separator-color`. See
  [Breadcrumb → CSS variables](/colorffy-ui/components/breadcrumb#css-variables).
- **Stepper CSS variables.** Steppers read 24 public variables for the
  indicator size, corners, text and pending, current and completed colors, the
  connector, labels, descriptions, the vertical gap and motion. See
  [Stepper → CSS variables](/colorffy-ui/components/stepper#css-variables).

### Changed

- **The sidebar's active-icon color is a public variable.** The leading icon of
  the current-route item read `--_drawer-active-color`, a private variable
  nothing declared. Set `--sidebar-item-active-icon-color` instead.

### Fixed

- **List items animate their background and border.** The item transition had
  no duration, so hover, pressed and active changes snapped. They now ease over
  `--duration-200`.

## 2.8.0

### Added

- **Duration tokens.** `--duration-100`, `-150`, `-200`, `-250`, `-300`,
  `-400`, `-500`, `-600` and `-800` are milliseconds derived from
  `--duration-unit` (`1ms`), and every component transition reads them, so
  `--duration-unit: .8ms` speeds up all motion by 20%, globally or for one
  subtree. Long looping animations (spinners, shimmers) keep their own timing.

### Changed

- **Ripples, the spinner and the galaxy gradient follow the theme.**
  `ripple-primary` / `ripple-secondary` and the spinner's color cycle used the
  compiled `$primary` … `$success` colors, so they ignored your brand tokens and
  dark mode; they now use `--theme-{color}-base`. The white and dark ripples use
  the brand white and black tokens, and `gradient-fuchsia` starts and ends on
  `--color-brand-accent-500`.
- **The SCSS color and font variables are deprecated.** `$primary`,
  `$secondary`, `$accent`, `$success`, `$warning`, `$danger`, `$info`, `$muted`,
  `$primary-colors` and `$font-*` are no longer read anywhere; they still compile
  so existing `@forward … with` configurations keep building, and they will be
  removed in 3.0. Set the `--color-brand-*` and `--font-*` tokens instead (see
  [customization](/colorffy-css/customization)).

### Removed

- **Private variables that never did anything:** `--_dialog-easing-out`,
  `--_dialog-easing-out-duration`, `--_navigation-bar-easing-out-duration`,
  `--_nav-tabs-gutter-y`, `--_shape-offset` and `--_container-gutter-y`. They
  were declared but never read, so overriding them had no effect.

### Fixed

- **Alerts with an icon stack in narrow containers.** Below 350px the alert
  set `--_alert-flex-direction: column`, but `.alert-content` wrote
  `flex-direction: row` directly, so the icon never moved above the text. The
  content now reads the variable and left-aligns when stacked.
- **Tab colors go through the button variables.** `.tab-link` set `color` and
  the hover `background` directly, overriding `--_btn-color` and
  `--_btn-bg-color`, so setting those had no effect. The rest, hover and active
  states now set the variables; the rendered colors are unchanged.
- **`--_progress-color` sets the progress bar fill**, and
  **`--_table-bg-color` / `--_table-color` set the table's background and text
  color.** They were declared but never applied. Their defaults now match what
  rendered before (`transparent` and `currentColor` for the table).

## 2.7.0

### Added

- **`UiTabs` takes `fit` and `rounded`.** `fit` makes the tab bar only as wide
  as its tabs instead of spanning its container (ignored with `fluid`).
  `rounded` makes pill tabs and their indicator fully rounded; it only applies
  with `pillTabs`. Both radii come from one private variable,
  `--_nav-tabs-item-radius`.
- **`UiAvatar` and `UiAvatarGroup` take a `color` prop.** It tints initials and
  placeholder avatars with any theme color, at the color's fixed tone and 25%
  opacity, in place of adding a `bg-*-fixed` class. On the group it applies to
  every avatar and the "+N" overflow avatar, and `avatars` entries can override
  it. The CSS classes are `.avatar-{color}`, driven by `--_initials-base-color`
  and `--_initials-alpha`.
- **`UiAvatar` and `UiAvatarGroup` take a `variant` prop.** `transparent` is
  the see-through tint, `tonal` the same tint made opaque, and `filled` the
  full theme color with its on-color text (`.avatar-tonal`, `.avatar-filled`).
  `UiAvatar` defaults to `transparent`; `UiAvatarGroup` defaults to `tonal`.
- **`border-neutral`, `border-black` and `border-opacity-*`.** `border-neutral`
  uses the body text color, so it flips with dark mode; `border-black` matches
  `text-black`. `border-opacity-{0…100}` fades any border color toward
  transparent with `color-mix()` in `oklab`.
- **Shape, weight, motion and focus tokens.** `--radius-*`,
  `--border-width-sm` / `-md`, `--fw-400…800`, `--ease-*` and
  `--focus-ring-color` / `--focus-ring-offset` are CSS custom properties on
  `:root`, and every component reads them. Override them at runtime without
  recompiling; the SCSS variables still set their defaults. See
  [customization](/colorffy-css/customization).

### Changed

- **Avatars in a `UiAvatarGroup` are opaque.** Initials and the "+N" overflow
  avatar used a 25% transparent background, so the image they overlap showed
  through. The group now defaults to `variant="tonal"`, the same tint made
  opaque; pass `variant="transparent"` for the previous look.
- **Easing curves no longer have `cubic-bezier()` fallbacks.** `linear()` is
  supported in every current browser, so the 25 `@supports` blocks that swapped
  them in are gone and each component declares its curve once. Browsers
  without `linear()` support (before Chrome 113, Firefox 112 and Safari 17.2)
  now skip those transitions instead of using a simpler curve.
- **Reduced motion calms the overshooting curves.** Under
  `prefers-reduced-motion: reduce`, `--ease-spring`, `--ease-overshoot-soft` and
  `--ease-bounce` resolve to `--ease-decelerate`, so dialogs, dropdowns,
  avatars and the rest of the components using them settle without overshooting
  or bouncing.
- **Font sizes are in `rem`, not `px`.** The 17 remaining pixel font sizes
  (body text, buttons, tables, tooltips, badges, icons) render the same at the
  default browser size and now follow the user's font-size setting. If your
  site changes the root font size (e.g. `html { font-size: 62.5% }`), these
  now scale with it like the spacing and `--fs-*` tokens already did: body
  text set to `.875rem` renders at 8.75px with a 10px root.
- **Full-height layouts use `dvh`.** The sidebar, dialogs, the PrimeVue dialog
  and `.pane-content` size themselves with dynamic viewport units, so mobile
  browser toolbars no longer push them past the visible area. The `.vh-*`
  utilities keep `vh`.
- **`--fs-xs` no longer shrinks below `--fs-2xs`.** Its minimum was `0.60rem`,
  smaller than `--fs-3xs` and `--fs-2xs`, so on narrow screens "xs" text
  rendered smaller than the steps below it. The minimum is now `0.75rem`.
- **`border-white` and `border-dark` use the brand color tokens**
  (`--color-brand-white-500`, `--color-brand-dark-500`), like `text-white` and
  `text-dark`, instead of compiled SCSS colors.

### Fixed

- **Focused inputs are visible in forced-colors mode.** Form controls drew
  their focus ring with `box-shadow` and removed the outline; forced-colors
  mode (Windows High Contrast) drops box-shadows, so focus disappeared. They
  now add a `Highlight` outline under `@media (forced-colors: active)`.
- **The progress bar transition always has a duration.**
  `--_progress-easing-duration` was only declared inside the `linear()`
  `@supports` block; it is now part of `.progress`'s defaults.
- **`border-animated` glows without a gradient preset.** Its glow is a
  `conic-gradient()` of `--_border-gradient`, which only the `gradient-{name}`
  classes set, so on its own the gradient was invalid, the background was
  dropped and nothing showed. It now defaults to the same primary gradient as
  `border-gradient`.
- **`border-animated` stops spinning under reduced motion.** Its `::before` and
  `::after` ran `angle-spin` with no `prefers-reduced-motion` check, unlike
  `border-gradient-spin`. Under `prefers-reduced-motion: reduce` the animation
  is now `none`, so the glow stays still at its starting angle.

## 2.6.1

### Fixed

- **Shimmer skeletons render again.** `.skeleton-shimmer` built its gradient
  from `--theme-muted-a5`, a token that doesn't exist, so the whole background
  was dropped and the skeleton was invisible. The highlight is now the muted
  tone at half opacity.
- **The segmented control's easing variable is spelled correctly.** It was
  declared as `--_sc_easing-in` but read as `--_sc-easing-in`, so browsers
  without `linear()` support got no transition.
- **The side-sheet dialog's fallback animation uses an easing curve.** Its
  `animation-timing-function` read `--_dialog-easing-duration` (a duration)
  instead of `--_dialog-easing-in`.
- **The active menu-tools subtitle in the navbar is primary-colored.** It
  referenced `--theme-primary-a0`, which doesn't exist; it now uses
  `--theme-primary-a10`.
- **The navigation bar's reduced-motion indicator fades with its own easing.**
  It referenced the undefined `--easing-in` / `--easing-out`; it now uses
  `--_navigation-bar-easing-in` / `--_navigation-bar-easing-out`.
- **Private variables that were declared but ignored now apply:**
  - `--_drawer-radius` sets the sidebar's corners. It held the wrong corners
    and the radius was written directly; `drawer-bordered` sets it to `0`.
  - `--_dropdown-shadow` sets the dropdown panel's shadow.
  - `--_table-border-color` sets every table border.
  - `--_form-check-input-active-border-color` (previously the misspelled
    `--_form-check-input-activeborder-color`) sets a checked input's border.

  Their defaults match what rendered before, so nothing changes visually
  unless you override them.
- **`.icon-wrap` no longer emits an invalid border.**
  `--_icon-wrap-border-size` defaulted to `none`, which isn't a width; it is
  now `0`.

## 2.6.0

### Added

- **`UiTabs` takes a `size` prop.** `size="sm"` adds `.tabs-sm`, which puts the
  tab buttons back on the default button height, padding, icon size and font
  size instead of the larger tab defaults. `md` (or leaving it unset) keeps the
  current size.
- **The `btn-size` mixin has an `md` step.** It emits the default `.btn`
  sizing, so a component that enlarges its buttons can reset them in one line;
  `.tabs-sm` uses it.
- **`UiDatatable` toolbar slots.** `#actions-start` and `#actions-end` add
  your own buttons to the built-in column button group, before and after it.
  `#column-toggle` and `#column-manager` replace the built-in buttons and
  receive the column state (`columns`, `allVisible`, `isVisible`, `isLocked`,
  `toggle`, `toggleAll`, typed as `IDatatableColumnSlotProps`), so a custom
  control drives the same visibility logic.
- **`UiDatatable` takes a `toolbarButton` prop.** One object (`variant`,
  `color`, `size`, `customClass`, `rounded`) restyles both built-in toolbar
  buttons, instead of a prop per button per option.
- **`UiDatatable` takes a `stickyHeight` prop.** It sets the sticky scroll
  container's max height (`sticky-height="18rem"`; a number is read as pixels),
  replacing the inline `--_table-sticky-max-height` style binding. The variable
  still works and still defaults to `32rem`.

### Changed

- **`UiDatatable`'s column manager is an icon-only button.** It shows the
  `view_column` icon with the same outline, small, `shape-sm` style as the
  column toggle beside it; `columnManagerTooltip` is its tooltip and
  accessible name.

- **`UiInputFile` reads the shared `size` prop.** `size="lg"` renders the
  taller dropbox. The input already inherited `size` from the base input props
  but ignored it, so the dropbox had its own `large` boolean; `large` still
  works but is deprecated in favour of `size="lg"`.

### Removed

- **`UiDatatable`'s `columnManagerText` prop.** The column manager button has
  no label anymore; drop the prop, or move the wording to
  `columnManagerTooltip`.

### Fixed

- **Text-only tabs are no longer wider on the right.** `.tab-link` kept the
  button grid's two columns and a `--space-4` gap even with nothing in the
  second column, adding 4px after the label; a tab with an icon but no badge
  got the same phantom gap. Tab links now lay out with flex, so the gap only
  sits between items that exist. As a side effect, `fluid` tabs with an icon
  centre the icon, label and badge together instead of pinning the icon to the
  left edge.
- **`UiDatatable`'s toolbar renders for `#controls` alone.** It only rendered
  when a column started hidden or `column-manager` was on, so a table using
  just the `#controls` slot showed nothing. Any toolbar slot now renders it.
- **`UiDatatable` toolbar ids are unique per table.** The column toggle, column
  manager and each menu item used fixed ids (`columns-toggle`,
  `column-manager`, `column-<key>`), which collided with two tables on one
  page. They are now prefixed with a per-instance id.
- **`UiButtonTooltip` and `UiButtonMenu` no longer share ids.**
  `UiButtonTooltip` defaulted `id` to `'tooltip'`, so every instance without
  an id rendered `button-tooltip`; `UiButtonMenu` built `-dropdown` and
  `-tooltip` popper ids from an empty id. Both now default to no id and leave
  the popper id to floating-vue unless you pass one, like `UiLinkTooltip`.
- **`UiDatatable`'s default empty-state subtitle reads correctly.** "Try may
  want to try…" is now "You may want to try…".

## 2.5.1

### Added

- **`UiFooter`, `UiFooterGroup` and `UiFooterItem`.** The footer styles existed
  in `@colorffy/css` with nothing rendering them; these cover the brand block,
  the link groups (column or row) and the links themselves, including the
  plain `.anchor-link` entry for a group member with no target. `UiFooter`
  supplies its own container and takes the same `fluid` prop as `UiNavbar`,
  plus a `#bottom` slot for the divided bar under the groups; `UiFooterGroup`
  takes `overline` for a small uppercase heading.
- **`UiHeroContent`.** A page-opening hero: eyebrow, display-sized title,
  description and a `#actions` slot for CTAs, with `size` selecting the display
  step and `align` moving the whole block.
- **`UiSubheadingContent`.** A section subheading with an optional description,
  built on `.text-subheading`, with `as` to keep the heading order valid, a
  `gutter` prop for the space below it, and an `#actions` slot for a badge or
  control beside it.

### Changed

- **`.text-subheading` uses the type tokens.** It picks up
  `--fs-lg--line-height` and the `--space-*` gutters, and no longer runs the
  `text-variable` mixin: it sets `--font-primary` directly, which every font
  honours.
- **Chips split the container from the selected color.** `.btn-chip` is the
  outline container and `.chip-elevated` the raised one; the color classes
  (`.chip-primary`, `.chip-secondary`, `.chip-neutral`) only apply together with
  `.chip-active`. `.a40` and `.a60` are removed, and `.chip-active` no longer
  forces a pill radius. See
  [the migration note](/migration#chips-split-the-container-from-the-selected-color).

- **`UiHeaderContent` renamed `hideActionsOnMobile` to `hideActionsWhenNarrow`,
  defaulting to `false`.** The old name described a device, but the mechanism is
  a container query: a narrow header collapses inside a wide window too. The old
  default also destroyed the page's primary actions below 700px unless you opted
  out, so hiding them is now something you opt in to; otherwise they wrap below
  the title.
- **`UiHeaderContent` emits `back` instead of `click`.** Declaring `click` as an
  emit meant a consumer's `@click` never attached as a native listener — it
  fired only for the back button. `@click` now behaves like any other native
  listener, and `@back` carries the intent.
- **`UiHeaderContent`'s `containerClass` accepts `ClassValue`.** It previously
  took `string | string[]` and stringified the object form to `[object Object]`.
  Existing values keep working.

- **`UiPaneContent`'s `customClass` and `containerClass` accept `ClassValue`.**
  Same widening as `UiHeaderContent`; existing values keep working.
- **The page header's back-navigation class is `.page-header-back`.** It was
  `.page-header-breadcrumb`, which described a component the header does not
  render. The back button is also centred against the title block now, instead
  of aligning to its top edge.
- **The header's bottom margin moved to `.header-container` and has its own
  token.** `--_header-block-end` and `--_header-back-gap` split out of
  `--_header-columns-gap`, which was setting the title/actions gap and the space
  below the header at once. The margin sat on the inner `.header`, so a padded
  or tinted container trapped it inside its own box and a `mb-*` utility on the
  container stacked on top of it. On the container it is a single margin that
  utilities override, since `utilities` is layered after `components`.

- **`UiHeaderContent` takes an `as` prop.** The title was always an `h1`, so a
  page using the component for its section headers emitted several. It defaults
  to `h1`; pass `as="h2"` and below for sections.
- **`UiHeaderContent` takes a `headline` prop.** It renders a small eyebrow
  label above the title with `caption text-primary`.
- **`UiHeaderContent` takes a `size` prop.** `sm` (the default, `--fs-xl`)
  through `2xl` (`--fs-5xl`), each step also applying the line height the type
  scale pairs with it. `UiHeroContent` uses the same `sm`–`xl` vocabulary on the
  display scale, so one size language covers both.
- **The header title no longer uses the `text-variable` mixin, and its 992px
  breakpoint is gone.** The mixin pinned the title to `wght`/`GRAD`/`wdth`
  variation axes that most families do not ship, and swapped the typeface behind
  an `@supports` test; `$type-h1` already gives the `h1` the same family and
  weight in a way every font honours. The breakpoint then swapped `--fs-xl` for
  `--fs-lg`, but the `--fs-*` scale is already fluid, so the title shrank twice
  and landed at 16px on a phone. It now scales once, 20px to 24px.

- **`UiHeaderContent` and `UiHeroContent` take a `viewTransitionName` prop.**
  The header hard-coded `view-transition-name: selected-header` on every title
  and `selected-description` on every description. A name has to be unique per
  document, so a page with more than one header — a page title plus its section
  headers — made the browser skip the transition entirely rather than run it.
  The name is also the key pairing two pages, which only the app knows, so it
  is now passed in and nothing is emitted without it. `contain: paint` and the
  `fit-content` inline size come with it instead of applying to every header.

- **The footer's gradient underlay, hover radius and rounded top corners, and
  `.dialog-highlight`.** Both drew a gradient through a pseudo-element; the
  footer also squared its top corners on hover, and its corners are now flat
  with no radius transition left to animate.
- **`.footer-row` declares its own direction.** It set a custom property the
  base rule never read, so a row group was horizontal only because that is the
  flex default. A row group with a title now keeps the heading on its own line
  instead of inline with the links.

- **Card surfaces are static and interaction is its own class.**
  `.card-outline`, `.card-pane` and `.card-elevated` now only describe the
  surface; `.card-selectable` and `.card-link` carry every hover, press and
  focus state, including the elevated card's `sm` → `md` → `lg` shadow
  escalation. A plain elevated card previously animated its shadow with nothing
  clickable behind it. `.card-link` also picks up the same background feedback
  as a selectable card, which it had diverged from. See
  [the migration note](/migration#card-surfaces-are-static-and-interaction-is-its-own-class).
- **The selectable card keeps its variant's border and its own radius.** It set
  a 2px transparent border to reserve room for the selected ring; with
  `box-sizing: border-box` the outer box never moved anyway, so the ring is a
  1px border that matches a static `.card-outline` beside it. The selected and
  pressed states also hard-coded `$rounded-lg` / `$rounded-xl`, which ignored a
  configured `$card-border-radius` — on a 4px theme, clicking a card ran it
  4px → 25px → 12px and left it there. The radius no longer changes.
- **The selectable card's ring answers `:focus-visible`.** It was `:focus`, so
  a mouse click left the ring on the card until it lost focus.
- **The selectable card's hover lift is 4px.** It was 8px, which read as a
  drag rather than a hover; `card-sm` steps down to 2px alongside it.

### Removed

- **`UiHeaderContent`'s `actions` prop.** Filling the `#actions` slot is the
  signal; passing the slot without the flag used to render nothing, silently.
- **`.subheading-m2`.** It set the same gutter `.text-subheading` already
  defaults to, so it never changed anything, and the reference documented it as
  a "large margin" it could not produce. `subheading-m1` and `subheading-m0`
  stay for a tighter gutter or none.
- **`@colorffy/ui`'s `./style.css` export.** The package no longer emits a
  stylesheet: its one scoped style block moved into `@colorffy/css`, which every
  consumer already loads. Nothing referenced the export, and it now pointed at a
  file that is not built.
- **`.page-header-featured` and the header's `.col-heading` / `.col-actions`
  rules.** None of them had any markup behind them: the featured badge block
  styled a composition no component rendered, and the two media queries targeted
  classes that exist nowhere. The back-navigation and actions layouts are
  unaffected.

### Fixed

- **`subheading-m0` / `m1` now move the space below the block.** The modifiers
  set `--_text-subheading-gutter` on the heading, and a custom property never
  reaches a sibling, so the description below kept its default margin whichever
  modifier was applied. Each modifier now also sets the description's margin.
- **The title-to-description gap no longer follows the gutter.** It was half the
  gutter, so tightening the space below the block squeezed the title against its
  own description — 2px at `subheading-m1`. It is now its own
  `--_text-subheading-gap`, fixed at `--space-8`.
- **`.card-selectable` no longer erases the variant's border.**
  `.card-outline.card-selectable` and `.card-frosted.card-selectable` matched at
  the same specificity, and `.card-selectable` came last in the file, so its
  `--_card-border-color: transparent` won and the card rendered with no outline
  at all until it was pressed or selected. It no longer declares the colour at
  rest, which the base `.card` already defaults to transparent.
- **An interactive card's transitions all run.** `.card-selectable` and
  `.card-link` each declared their own `transition`, so on a card that was both
  — which `UiCard` produces whenever `selectable` meets `to`/`href` — the
  later rule won and the lift and the ring never animated. `box-shadow` was also
  missing from the selectable list, so an elevated card jumped straight to its
  hover shadow. One shared declaration now covers every interactive card.
  `--_card-easing-in` also has its non-`linear()` fallback back: it was only
  defined inside the `@supports` block, and an undefined custom property in a
  `transition` makes the whole declaration invalid at computed-value time, so
  without `linear()` support the card had no transition at all.
- **A `card-pane` card gives hover feedback in light mode.** The shared hover
  steps the background to `--theme-surface-overlay`, which resolves to the same
  white as the pane's own surface in a light theme — an interactive pane card
  changed nothing under the pointer. Pane now steps to `--theme-surface-a30`,
  which contrasts in both schemes, and carries its own press step so `:active`
  is not outranked by it.

#### The page header title scales down again

`.header` stepped its title down to `--fs-lg` below 992px through
`:where(.col-heading h1:is(.text-title))` — a selector that matched nothing, and
whose `:where()` wrapper would have given it zero specificity even if it had.
The size now flows through `--_header-title-size`, overridden inside the
`.header` rule itself, so it carries the same specificity as the value it
replaces.

#### The header's view transitions actually apply

`view-transition-name`, `contain: paint` and the `fit-content` inline size for
`.text-title` / `.text-description` lived in a Vue scoped style block that
compiled to `@colorffy/ui`'s `dist/ui.css` — a file nothing imported, so the
declarations never reached the page. They now live here in `_header.scss`
alongside the rest of the header rules.

#### Connected groups no longer flatten their inner corners

The rounded end of `.btn-group-connected` came from a fixed
`--_btn-connected-radius: 50px`. On a 32px-tall button that is 50px + 50px down
one side against a 32px box, and the spec answer to radii that overflow a side
is to scale **every corner of that element** by the same factor — here
`32 / 100`. The first button's inner corners, asking for the 4px of
`--_btn-radius`, rendered at 1.3px and read as square next to their siblings:

```
before   first: 50, 1.3, 1.3, 50   middle: 4, 4, 4, 4
after    first: 16, 4,   4,   16   middle: 4, 4, 4, 4
```

The radius is now derived from the button instead of hard-coded:

```scss
.btn-group-connected .btn {
  --_btn-connected-radius: calc(var(--_btn-height) / 2);
}
```

The two radii on a side then sum to exactly `--_btn-height`, which `min-height`
guarantees is never taller than the button, so the scale factor stays 1 and the
inner corners keep their own value. It also tracks the size variants — `btn-sm`,
`btn-lg` and `btn-icon` each get the pill that fits them.

::note
If you set `--_btn-connected-radius` yourself, move it onto the buttons
(`.btn-group-connected .btn`) — a declaration on the group is now shadowed by
the one above.
::

#### Vertical connected groups follow the button radius

`.btn-group-vertical.btn-group-connected` had three separate mismatches: middle
buttons were pinned to `$button-border-radius` instead of `--_btn-radius`, so a
group of `btn-sm` got 8px corners where the horizontal variant gave 4px; the
first and last button squared their inner corners to `0`, although the group is
separated by a gap; and the joined variant set `border-radius: 0` as a shorthand
that outranked the end rules, so vertical joined groups lost their pill ends
entirely. All three now behave like the horizontal variant.
