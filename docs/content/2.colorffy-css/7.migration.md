Colorffy CSS 2.5.0 standardized every spacing and font-size value onto design
tokens (CSS custom properties defined on `:root`). **Nothing breaks in 2.5** —
every old name keeps working through deprecated aliases — but new code should
use the new names, and 3.0 will remove the aliases.

## 2.0 → 2.5

### New spacing tokens

Spacing now uses a value-encoded numeric scale — the number is the pixel value
at the default 16px root — derived from a single unit:

```css
--space-unit: .25rem;
--space-4   /* 4px  */    --space-16  /* 16px */
--space-6   /* 6px  */    --space-20  /* 20px */
--space-8   /* 8px  */    --space-24  /* 24px */
--space-12  /* 12px */    --space-32  /* 32px */
--space-14  /* 14px */    --space-48  /* 48px */
```

All components consume these tokens, so you can retheme spacing at runtime:

```css
/* denser UI everywhere, proportionally */
:root { --space-unit: .2rem; }

/* or adjust one step */
:root { --space-12: .7rem; }
```

::note
The `m-*` / `p-*` / `gap-*` **utility classes** keep their own historical scale
(`1` = 0.25rem … `10` = 12rem) in 2.5 and are unaffected by these tokens.
::

### Font sizes renamed to a t-shirt scale

The old ordinal names (`--fs-100`, where a *smaller* number meant a *bigger*
size) are replaced by a t-shirt scale anchored at `--fs-base`. Values are
unchanged — same fluid `clamp()`s, new names:

| Deprecated (2.x alias) | New token | Max size |
|---|---|---|
| `--fs-sm-500` | `--fs-4xs` | 11px |
| `--fs-sm-400` | `--fs-3xs` | 12px |
| `--fs-sm-300` | `--fs-2xs` | 13px |
| `--fs-sm-200` | `--fs-xs` | 14px |
| `--fs-sm-100` | `--fs-sm` | 15px |
| `--fs-600` | `--fs-base` | 16px |
| `--fs-500` | `--fs-lg` | 20px |
| `--fs-400` | `--fs-xl` | 24px |
| `--fs-300` | `--fs-2xl` | 28px |
| `--fs-200` | `--fs-3xl` | 32px |
| `--fs-100` | `--fs-4xl` | 40px |
| `--fs-xl-100` | `--fs-5xl` | ~53px |

Every size also gained a **line-height companion** using the double-dash
suffix convention:

```css
.intro {
  font-size: var(--fs-lg);
  line-height: var(--fs-lg--line-height); /* 1.4 */
}
```

### New font-size utility classes

The new `.fs-4xs` … `.fs-5xl` classes set the size **and** its paired
line-height. The legacy classes (`.fs-100`…`.fs-600`, `.fs-sm-100`…`.fs-sm-500`,
`.fs-xl-100`) still work and still set font-size only, so existing markup
renders identically.

```html
<!-- 2.0 (still works, deprecated) -->
<p class="fs-500">Title</p>

<!-- 2.5 -->
<p class="fs-lg">Title</p>
```

### Deprecated in 2.5 (removed in 3.0)

- The 12 old font-size token names (aliases of the new tokens).
- The 13 legacy `.fs-*` utility classes.
- The `$space-1` / `$space-2` / `$space-3` SCSS variables — use
  `var(--space-16/32/48)`.

## 2.5 → 3.0 (planned breaking changes)

3.0 removes the deprecation layer and finishes the naming architecture:

1. **Font-size aliases removed** — rename per the table above. Note that
   moving markup from a legacy `.fs-*` class to its t-shirt equivalent also
   applies the companion line-height.
2. **Legacy `.fs-*` utility classes removed.**
3. **`$space-1/2/3` SCSS variables removed.**
4. **Namespace prefix** — public tokens gain a library prefix (planned
   `--cffy-`) to avoid collisions with other libraries on the same page
   (the way Bootstrap uses `--bs-*` and Material uses `--md-*`).
   Component-private `--_*` properties are unaffected.
5. **Spacing utilities rebased** — the `m-*`/`p-*`/`gap-*` classes move onto
   the token scale (px-numeric steps, e.g. `.p-12` = `var(--space-12)`), so
   the meaning of the old numeric steps (`.m-3` = 1rem) changes or is removed.
6. **`--container-*` width scale** (t-shirt) absorbs one-off dimensions such
   as `--theme-nav-drawer-width`.

Pin to `^2.5` to stay on the compatibility layer until you have migrated.
