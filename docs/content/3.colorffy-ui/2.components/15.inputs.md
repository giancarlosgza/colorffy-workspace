All Colorffy form inputs share a common base — `label`, `placeholder`, `disabled`, `required`, `readonly`, `errorMessages`, `variant`, `size`, `hideLabel` — and bind with `v-model`.

## Text and textarea

```vue
<script setup lang="ts">
import { ref } from 'vue'

const name = ref('')
const bio = ref('')
</script>

<template>
  <UiInputText v-model="name" label="Name" placeholder="Jane Doe" required />
  <UiInputTextarea v-model="bio" label="Bio" :rows="4" />
</template>
```

## Select

`options` accepts an array; map labels / values with `optionLabel` / `optionValue`:

```vue
<script setup lang="ts">
import { ref } from 'vue'

const role = ref(null)
const options = [
  { name: 'Admin', value: 'admin' },
  { name: 'User', value: 'user' },
]
</script>

<template>
  <UiInputSelect
    v-model="role"
    :options="options"
    option-label="name"
    option-value="value"
    label="Role"
  />
</template>
```

`UiInputSelect` is the native `<select>`, the better choice on phones for a short list. For a long list, a list to search, or options that need more than a line of text, use `UiInputCombobox`.

## Combobox

`UiInputCombobox` picks one value from a list you can search. It takes the same `options`, `optionLabel` and `optionValue` as `UiInputSelect`, plus the shared base props.

```vue
<script setup lang="ts">
import { ref } from 'vue'

const leadId = ref<string | null>(null)
</script>

<template>
  <UiInputCombobox
    id="lead"
    v-model="leadId"
    label="Project lead"
    placeholder="Search the team"
    :options="members"
    option-label="name"
    option-value="id"
    option-group="team"
    option-disabled="away"
    clearable
  >
    <template #option="{ option }">
      <UiAvatar :src="option.avatar" size="sm" />
      {{ option.name }}
    </template>
  </UiInputCombobox>
</template>
```

- **Searching.** Typing filters the options by label, ignoring case and accents, and highlights the first match. Leaving the field with text that matches an option exactly selects it; leaving it empty clears the value; anything else puts the selected label back.
- **Select-only.** Set `:filterable="false"` for a field that works like a select: typing jumps to the first option that starts with the typed letters.
- **Options.** `optionGroup` names the field that groups options under headings, in the order each group first appears, and `optionDisabled` the field that disables one. Without `optionValue`, the model holds the whole option and object options match by reference. The `#option` slot (`{ option, selected, active }`) renders each row, and `#empty` (`{ query }`) replaces `emptyText` (`'No results'`).
- **Keyboard.** ↓ and ↑ open the list and move through it, Page Down and Page Up jump ten options, Enter picks, and Esc closes the list. With `clearable`, a second Esc clears the value; inside a dialog, the dialog closes only on the Esc after that. Focus stays in the field the whole time.
- **The list** is a popover anchored to the field. It opens below and flips above when there isn't room, and it sits on top of dialogs and outside scrolling or clipping containers. Browsers without CSS anchor positioning get the same placement from a small script.

## Multi-select

`UiInputMultiSelect` picks several values from the same kind of list. The model is an array, in the order the values were picked; everything else works as on `UiInputCombobox`: `options`, `optionLabel`, `optionValue`, `optionGroup`, `optionDisabled`, `filterable`, `clearable` and the `#option` / `#empty` slots.

```vue
<script setup lang="ts">
import { ref } from 'vue'

const projectIds = ref<string[]>([])
</script>

<template>
  <UiInputMultiSelect
    id="projects"
    v-model="projectIds"
    label="Add to projects"
    placeholder="Search projects"
    :options="projects"
    option-label="name"
    option-value="id"
    option-group="status"
    :max="5"
    clearable
  />
</template>
```

- **Picking.** Enter or a click toggles the highlighted option, and the list stays open for the next one. A search clears after each pick.
- **The field** shows a chip per value, like `UiInputTags`: each chip has a remove button, and Backspace in an empty field removes the last one. Set `maxChips` to keep the field to one row: past that many values, the chips give way to the `maxChipsLabel` summary (`'{count} selected'`), long chip labels are cut with an ellipsis, and the summary steps aside while you search. `:max-chips="0"` always shows the summary, for tight spaces such as a toolbar filter.
- **Limits.** `max` caps the number of values; once it's reached, the other options are disabled until one is removed.
- **Events.** Besides `update:modelValue` and `update`, it emits `add` and `remove` with the value. Screen readers hear each change, and the field's description lists what's selected.

## Range, file, color, and phone

`UiInputFile`, `UiInputColorPicker`, and `UiInputCheck` share the same base props as the other inputs (`errorMessages`, `disabled`, `required`, `optionalLabel`, `hideLabel`) and bind with `v-model` like the rest:

```vue
<template>
  <UiInputRange v-model="volume" :min="0" :max="100" :step="5" label="Volume" />
  <UiInputFile v-model="file" label="Upload" input-label="Choose a file" :error-messages="fileErrors" />
  <UiInputPhoneNumber v-model="phone" label="Phone" />
  <UiInputColorPicker v-model="color" label="Brand color" :maxlength="7" />
</template>
```

`size="sm"` on `UiInputRange` shrinks the track and the thumb along with the field, for dense forms and toolbars:

```vue
<template>
  <UiInputRange v-model="zoom" size="sm" label="Zoom" />
</template>
```

## OTP Input

`UiInputOtp` renders one box per character of a segmented PIN or verification code. It auto-advances focus as boxes fill, supports Backspace/Arrow key navigation, and distributes pasted (or autofilled) codes across boxes. `modelValue` is always a plain string; `length` (default `6`) controls the number of boxes.

```vue
<script setup lang="ts">
import { ref } from 'vue'

const code = ref('')

function handleComplete(value: string) {
  console.log('Code complete:', value)
}
</script>

<template>
  <UiInputOtp v-model="code" label="Verification code" @complete="handleComplete" />
  <UiInputOtp v-model="pin" label="4-digit PIN" :length="4" />
</template>
```

**Props:** `length` (default `6`), `integerOnly` (default `true` — numeric `inputmode`, non-digit characters discarded on input/paste; set to `false` for alphanumeric codes), `autofocus`, plus the shared base props (`errorMessages`, `disabled`, `required`, `readonly`, `variant`, `size`, `rounded`, `hideLabel`).

**Events:** `update:modelValue`, `update`, and `complete` — fired once with the full value when every box is filled.

## Password, search and tags

`UiInputPassword`, `UiInputSearch` and `UiInputTags` take the shared base props, so `id`, `label`, `errorMessages`, `variant`, `size` and `rounded` behave as on the other inputs.

```vue
<script setup lang="ts">
import { ref } from 'vue'

const password = ref('')
const query = ref('')
const emails = ref<string[]>([])
</script>

<template>
  <UiInputPassword id="password" v-model="password" label="Password" autocomplete="new-password" />

  <UiInputSearch id="search" v-model="query" label="Search projects" hide-label placeholder="Search" @search="runSearch" />

  <UiInputTags id="emails" v-model="emails" label="Invite by email" placeholder="name@company.com" :max="10" />
</template>
```

- **`UiInputPassword`** shows or hides the password with an eye button inside the field. The button's accessible name stays `revealLabel` (`'Show password'`) and its `aria-pressed` tells whether the password is visible; bind `v-model:revealed` to control it. `autocomplete` defaults to `'current-password'` and `maxlength` to `128`.
- **`UiInputSearch`** puts a search icon inside the field, and a clear button once it holds text. Enter emits `search` with the value; the clear button or Esc empties the field and emits `clear`. Inside a dialog, the first Esc clears the field and the next one closes the dialog. `autocomplete` defaults to `'off'` and `maxlength` to `50`, as on `UiInputText`; `clearLabel` names the clear button. A disabled or read-only field ignores Esc.
- **`UiInputTags`** keeps a `string[]`. Enter or the `separator` (default `,`) adds the typed tag, Backspace on an empty field removes the last one, and pasted lines become one tag each. Duplicates are ignored without case unless `allowDuplicates` is set; `max` caps the count and `maxlength` (default `50`) the length of each tag. It emits `add` and `remove` with the tag, and announces both to screen readers.

## Prefix and suffix

`UiInputText` exposes `#prefix` and `#suffix` named slots. By default, content in either slot gets a bordered box attached to the input — useful for units. Set `adornments="inline"` to place it inside the field instead, for icons and icon buttons:

```vue
<template>
  <UiInputText v-model="search" label="Search">
    <template #prefix>
      <UiIconMaterial icon-code="&#xe8b6;" />
    </template>
  </UiInputText>

  <UiInputText v-model="price" label="Price" type="number">
    <template #prefix>
      $
    </template>
    <template #suffix>
      USD
    </template>
  </UiInputText>

  <UiInputText v-model="site" label="Website" adornments="inline">
    <template #prefix>
      <UiIconMaterial icon-code="&#xe894;" />
    </template>
  </UiInputText>
</template>
```

## Shared base props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `label` | `string \| null` | — | Field label. |
| `placeholder` | `string \| null` | — | Placeholder text. |
| `errorMessages` | `string[]` | — | Validation messages shown below the field. |
| `variant` | `'filled' \| 'outline' \| 'transparent' \| null` | — | Visual style. |
| `size` | `'sm' \| 'lg' \| null` | — | Field size. |
| `disabled` / `required` / `readonly` / `rounded` | `boolean` | `false` | Field states. |
| `hideLabel` | `boolean` | `false` | Visually hide the label. |

## CSS variables

Set these on `:root`, or on any wrapper to restyle only the fields inside it. They style text inputs, textareas and selects, and the color picker's field reads the same surface, border, radius and focus variables. The outline, rounded, transparent, `sm` and `lg` styles keep their own values, and disabled fields keep their muted look.

```css
:root {
  --cffy-input-radius: var(--cffy-radius-full);
  --cffy-input-padding-inline: var(--cffy-space-14);
  --cffy-input-focus-border-color: var(--cffy-accent-a10);
}
```

| Variable | Default | Controls |
|----------|---------|----------|
| `--cffy-input-height` | `2.5rem` | Field height |
| `--cffy-input-padding-inline` / `--cffy-input-padding-block` | `--cffy-space-8` / `--cffy-space-4` | Field padding |
| `--cffy-input-radius` | `$form-border-radius` (8px) | Corners |
| `--cffy-input-bg-color` / `--cffy-input-color` | `transparent` / `--cffy-on-background` | Background and text |
| `--cffy-input-border-width` / `--cffy-input-border-color` | `1px` / `--cffy-outline-text-field` | Border |
| `--cffy-input-font-size` | `0.875rem` | Text size |
| `--cffy-input-shadow` | `--cffy-shadow-xs` | Resting shadow |
| `--cffy-input-placeholder-color` | `--cffy-muted-a10` at 65% | Placeholder text |
| `--cffy-input-filled-bg-color` | `--cffy-surface-container-high` | Background of `.form-filled` fields |
| `--cffy-input-hover-border-color` | `--cffy-on-background` | Hovered border |

| `--cffy-input-easing` / `--cffy-input-duration` | `--cffy-ease-emphasized` / `--cffy-duration-300` | Background, border and ring transitions |

### Prefix and suffix CSS variables

The `prefix` and `suffix` adornments (`.input-group-prefix`, `.input-group-suffix`) follow the field's `--cffy-input-radius`, `--cffy-input-border-width`, `--cffy-input-border-color` and `--cffy-input-bg-color`, so they stay joined to it. These override the rest:

| Variable | Default | Controls |
|----------|---------|----------|
| `--cffy-input-group-bg-color` | `--cffy-input-bg-color` | Adornment background |
| `--cffy-input-group-color` | `--cffy-muted-a10` | Adornment text and icon |
| `--cffy-input-group-padding-inline` | `0.5rem` | Adornment padding |
| `--cffy-input-group-font-size` / `--cffy-input-group-icon-size` | `--cffy-fs-2xs` / `--cffy-fs-base` | Adornment text and icon size |

With `.input-group-inline` (`adornments="inline"`), the adornments sit inside the field as squares the height of the input, and the input pads itself to clear them. A second `.input-group-suffix` sits next to the first, as the combobox's clear and toggle buttons do. The input stays the bordered element, so focus, invalid, variants and sizes are unchanged.

### Tags CSS variables

`UiInputTags` (`.form-tags`) is a field-styled wrapper around the tags and a borderless `.form-tags-input`: it reads the same `--cffy-input-*` variables as a text field, grows in height as tags wrap, and shows focus with `:focus-within`. The tags are compact `.btn-chip.chip-closable` chips sized to the field, with their corners nested inside the field's (`--cffy-input-radius` minus the border and padding), so a rounded field gets pill-shaped tags. Once it holds a tag, the field uses its block padding on the start edge too, so tags sit the same distance from every edge; an empty field keeps the text padding.

| Variable | Default | Controls |
|----------|---------|----------|
| `--cffy-input-tags-gap` | `--cffy-space-4` | Space between tags and the text cursor |

### OTP CSS variables

`UiInputOtp` (`.form-otp`) boxes are square text fields: they take their size from `--cffy-input-height` and their surface, border and focus from the other `--cffy-input-*` variables. These set the rest:

| Variable | Default | Controls |
|----------|---------|----------|
| `--cffy-input-otp-gap` | `0.5rem` | Space between boxes |
| `--cffy-input-otp-font-size` / `--cffy-input-otp-font-weight` | `--cffy-fs-base` / `--cffy-fw-500` | Digit text |
