A settings screen splits account and app preferences into tabs, then into cards of setting rows: a title and a hint on the left, the control on the right. Use it for any page where the user reviews and changes many independent values.

![Settings page with Profile, Appearance, Notifications and Security tabs above a Profile card that holds a photo row, a two-column grid of name, email, job title and phone fields, and a Save changes button](/recipes/settings.jpg)

## Anatomy

1. **Page header**: title and one line on what the page covers. [UiHeaderContent](/colorffy-ui/components/layout)
2. **Tab bar**: one tab per area, synced with `?tab=` in the URL, with an optional badge for a pending action. [UiTabs](/colorffy-ui/components/tabs)
3. **Tab panel**: a `<section role="tabpanel">` per tab inside `<Transition name="fade">`, stacking its cards with `d-grid gap-6`.
4. **Settings card**: a `#header` with `.card-title` and a caption, setting rows in `#body`, a right-aligned save button in `#footer`. [UiCard](/colorffy-ui/components/card)
5. **Setting row**: a `row` with a label column (`fw-700` title, `caption text-muted` hint) and a control column, separated from the next row by a divider. [UiDivider](/colorffy-ui/components/divider), [inputs](/colorffy-ui/components/inputs)
6. **Profile**: photo with [UiAvatar](/colorffy-ui/components/avatar) and `UiInputFile`, then a two-column grid of `UiInputText` fields.
7. **Notifications**: a table of events by channel, one `UiInputCheck variant="switch"` per cell.
8. **Security**: two-factor setup with `UiInputOtp`, active sessions in a flush [UiListGroup](/colorffy-ui/components/list), and a danger zone with a [UiAlert](/colorffy-ui/components/alert) that opens a [UiConfirmModal](/colorffy-ui/components/modal).

```vue [pages/settings.vue]
definePageMeta({ pageTitle: 'Settings' })

/** Data */
const tabs: ITabItem[] = [
  { id: 'profile', label: 'Profile', icon: '&#xe7fd;', panelId: 'settings-profile' },
  { id: 'notifications', label: 'Notifications', icon: '&#xe7f4;', panelId: 'settings-notifications' },
  { id: 'security', label: 'Security', icon: '&#xe897;', panelId: 'settings-security' }
]
const profile = reactive<Record<'name' | 'email', string | number | null>>({ name: 'Maya Chen', email: 'maya@orbit.app' })
const savingProfile = ref(false)
const channels = [{ id: 'email', label: 'Email' }, { id: 'push', label: 'Push' }] as const
const events = [
  { id: 'mentions', label: 'Mentions', description: 'Someone @mentions you in a task or comment.' },
  { id: 'assignments', label: 'Assignments', description: 'A task is assigned to you or its due date moves.' }
] as const
const prefs = reactive<Record<'mentions' | 'assignments', Record<'email' | 'push', boolean>>>({
  mentions: { email: true, push: true },
  assignments: { email: true, push: false }
})
const deleteModal = ref<IDialogDisplay | null>(null)
const deleting = ref(false)

/** Composables */
const route = useRoute()
const router = useRouter()

/** Computed */
const activeTab = computed(() => tabs.find(tab => tab.id === route.query.tab)?.id ?? 'profile')

/** Methods */
function selectTab(id: string): void {
  router.replace({ query: { ...route.query, tab: id } })
}
async function saveProfile(): Promise<void> {
  savingProfile.value = true

}
async function deleteWorkspace(): Promise<void> {
  deleting.value = true

}
</script>
```

## Sync the tabs with the URL

The active tab is computed from `route.query.tab`, and picking a tab writes it back with `router.replace`. The URL stays the single source of truth: a link such as `/settings?tab=security` opens the right panel, the back button doesn't step through every tab, and an unknown value falls back to the first tab.

A tab can flag something that needs attention with `badge`. Make the tab list a computed when the badge depends on state:

```ts
const tabs = computed<ITabItem[]>(() => [
  { id: 'profile', label: 'Profile', icon: '&#xe7fd;', panelId: 'settings-profile' },
  {
    id: 'security',
    label: 'Security',
    icon: '&#xe897;',
    panelId: 'settings-security',
    badge: twoFactorEnabled.value ? null : { text: '1', variant: 'warning', pill: true }
  }
])
```

Only the active panel is rendered (`v-if` / `v-else-if`), and `<Transition name="fade" mode="out-in">` fades the old panel out before the new one comes in. The `fade` classes ship with Colorffy CSS.

## The setting row

Every preference uses the same two-column row, so the eye scans titles down the left and controls down the right:

```vue
<div class="row align-items-center">
  <div class="col-12 col-md-5">
    <p class="fw-700 mb-1">Reduce motion</p>
    <p class="caption text-muted mb-3 mb-md-0">Turns off animated transitions between pages.</p>
  </div>
  <div class="col-12 col-md-7">
    <UiInputCheck id="reduce-motion" v-model="reduceMotion" variant="switch" :label="reduceMotion ? 'On' : 'Off'" />
  </div>
</div>
<UiDivider custom-class="my-4" />
```

- Use `col-md-4` / `col-md-8` when the control is a form (several fields, a textarea), and `col-md-5` / `col-md-7` when it is one short control (a switch, a range, a segmented picker).
- Add `align-items-center` when the control is a single line. Leave it off when the control column holds several fields, so the title lines up with the first one.
- The hint takes `mb-3 mb-md-0`: below `md` the columns stack, and the margin separates the hint from the control under it.
- The row title already names the control, so the input's own label can be hidden with `hide-label`. It still names the field for assistive technology.
- Separate rows with `UiDivider custom-class="my-4"`. Separate groups of rows with a new card, not a thicker divider.

## Profile fields

Two-column fields sit in a grid on the control column: `d-grid grid-repeat-cols-1 grid-repeat-cols-sm-2 gap-inline-4`. Inputs carry their own bottom margin, so the grid only needs an inline gap. Validate with `:error-messages` and keep the save button disabled while a required field is invalid:

```ts
const profileErrors = computed(() => ({
  name: String(profile.name ?? '').trim() ? [] : ['Add your name so teammates can find you.'],
  email: String(profile.email ?? '').includes('@') ? [] : ['Enter a valid email, like maya@orbit.app.']
}))
const profileInvalid = computed(() => profileErrors.value.name.length > 0 || profileErrors.value.email.length > 0)
```

The photo row comes first in the Profile card, above a divider. The avatar shows the chosen file before it is saved, next to a `UiInputFile` whose label the row title replaces:

```vue
<div class="row align-items-center">
  <div class="col-12 col-md-4">
    <p class="fw-700 mb-1">Photo</p>
    <p class="caption text-muted mb-3 mb-md-0">JPG, PNG or WebP. Up to 5 MB.</p>
  </div>
  <div class="col-12 col-md-8 d-flex align-items-center gap-4">
    <UiAvatar :src="photoPreview ?? user.avatar" :alt="`${user.name} profile photo`" size="md" class="flex-shrink-0" />
    <div class="flex-grow-1">
      <UiInputFile id="profile-photo" v-model="photo" label="Profile photo" hide-label input-label="Upload photo" :error-messages="photoErrors" />
      <UiButton v-if="photo" text="Remove photo" variant="text" size="sm" class="mt-2" @click="photo = null" />
    </div>
  </div>
</div>
<UiDivider custom-class="my-4" />
```

Check the type and size in a watcher, show the problem through the file input's `error-messages`, and revoke the object URL when it is replaced or the page unmounts:

```ts
watch(photo, (file) => {
  if (photoPreview.value)
    URL.revokeObjectURL(photoPreview.value)
  photoPreview.value = null
  photoErrors.value = []
  if (!file)
    return
  if (!file.type.startsWith('image/'))
    photoErrors.value = ['Choose a JPG, PNG or WebP image.']
  else if (file.size > 5 * 1024 * 1024)
    photoErrors.value = ['Photos can be up to 5 MB.']
  else
    photoPreview.value = URL.createObjectURL(file)
})
```

## Save footer

A card whose values apply on save ends with one `variant="filled" color="primary"` button in `#footer`, right-aligned with `d-flex justify-content-end gap-2`. `:loading` shows progress on the button itself and blocks a second click; `:disabled` holds it while the form is invalid. Confirm the save with a toast. Cards whose controls apply right away, such as the interface preferences, have no footer.

## Notification matrix

When the same switch repeats across events and channels, a table is easier to scan than one row per combination. Column headers take `scope="col"`, each event cell pairs a `fw-700 fs-xs` title with a `caption text-muted` description, and each switch is centered with `class="d-inline-flex gap-0"` on a `text-center` cell. The visible label is hidden, but each switch keeps a full one, such as "Push notifications for mentions", so it makes sense on its own. `table-responsive` lets the table scroll sideways on narrow screens instead of squeezing the description.

## Two-factor setup

The card header shows the state as a `UiBadge` on the right: `tonal tonal-success` "On" or `tonal tonal-warning` "Off". The body switches between the setup form and a confirmation inside its own `<Transition name="fade" mode="out-in">`.

```vue
<template>
  <UiCard variant="pane">
    <template #header>
      <div class="d-flex align-items-start justify-content-between gap-3">
        <div>
          <p class="card-title">Two-factor authentication</p>
          <p class="caption text-muted mb-0">Ask for a code from your phone when you sign in.</p>
        </div>
        <UiBadge v-if="twoFactorEnabled" text="On" variant="tonal tonal-success" icon-code="&#xe86c;" />
        <UiBadge v-else text="Off" variant="tonal tonal-warning" icon-code="&#xe002;" />
      </div>
    </template>
    <template #body>
      <Transition name="fade" mode="out-in">
        <div v-if="twoFactorEnabled" class="bg-success-container text-on-success-container rounded-lg p-3 d-flex flex-wrap align-items-center gap-3" role="status">
          <UiIconMaterial icon-code="&#xe86c;" class="fs-2xl" />
          <p class="fw-700 mb-0 flex-grow-1">Two-factor authentication is on</p>
          <UiButton text="Turn off" variant="text" size="sm" @click="twoFactorEnabled = false" />
        </div>
        <div v-else>
          <UiInputOtp id="two-factor-code" v-model="otp" label="Verification code" :length="6" :disabled="verifying" :error-messages="otpErrors" @complete="verify" />
          <UiButton text="Verify and turn on" variant="filled" color="primary" :loading="verifying" :disabled="otp.length < 6" @click="verify" />
        </div>
      </Transition>
    </template>
  </UiCard>
</template>
```

`@complete` fires when the sixth digit lands, so most users never press the button; it stays for users who paste a code or fix a typo. Both paths call the same `verify`, which returns early while a check is running. Clear `otpErrors` in a watcher on `otp` so the error goes away as soon as the user edits the code.

## Active sessions and the danger zone

The Security panel stacks two-factor, sessions and the danger zone, in that order. Sessions are a `UiListGroup variant="flush"`, which drops the list's own border inside the card. Each `UiListItem` sets `has-actions` and puts its action in `#list-action`: a `tonal tonal-success` "This device" badge for the current session, a `text` "Sign out" button for the others. A bulk action goes in the card's `#footer` as an `outline` button, disabled when there is nothing to sign out.

```vue
<template>
  <UiCard variant="pane">
    <template #header>
      <p class="card-title">Active sessions</p>
      <p class="caption text-muted mb-0">Devices signed in to your account in the last 30 days.</p>
    </template>
    <template #body>
      <UiListGroup variant="flush">
        <UiListItem v-for="session in sessions" :key="session.id" :title="session.device" :text="session.detail" :icon="session.icon" custom-icon-wrapper-class="bg-secondary-container" custom-icon-class="text-on-secondary-container" has-actions>
          <template #list-action>
            <UiBadge v-if="session.current" text="This device" variant="tonal tonal-success" size="sm" />
            <UiButton v-else text="Sign out" variant="text" size="sm" @click="signOut(session.id)" />
          </template>
        </UiListItem>
      </UiListGroup>
    </template>
    <template #footer>
      <UiButton text="Sign out of all other sessions" variant="outline" size="sm" :disabled="otherSessions === 0" @click="signOutOthers" />
    </template>
  </UiCard>
</template>
```

The danger zone is always the last card of the last tab. Its title takes `text-danger`, and the action sits in the `#actions` slot of a `UiAlert type="tonal" variant="danger"` that says what will be lost. The button only opens a `UiConfirmModal`; the deletion runs on `@confirm`, with `:is-loading` and `loading-label` on the modal while the request is in flight, and `closeDialog()` once it succeeds.

## Interface preferences

Preferences that apply on this device right away share one card of setting rows with no save footer. The theme row uses a small color-mode picker built on `UiTabs` in radio mode, and the density row a `UiButtonToggleGroup`:

```vue [components/ColorModePicker.vue]
<script setup lang="ts">
import type { ITabItem } from '@colorffy/ui'

/** Interfaces */
interface IColorModePickerProps {
  showLabels?: boolean
}

/** Props */
const { showLabels = true } = defineProps<IColorModePickerProps>()

/** Data */
// The saved preference only exists on the client, so the picker follows it after mount
const isMounted = ref<boolean>(false)
// Scoped ids keep the buttons unique when two pickers share a page
const idPrefix = useId()
const colorModeTabs: ITabItem[] = [
  { id: 'system', label: 'System', icon: '&#xe31e;' },
  { id: 'light', label: 'Light', icon: '&#xe518;' },
  { id: 'dark', label: 'Dark', icon: '&#xe51c;' }
]

/** Composables */
const colorMode = useColorMode()

/** Computed */
const activeTab = computed(() => isMounted.value ? colorMode.preference : 'system')

/** Methods */
function selectColorMode(mode: string): void {
  colorMode.preference = mode
}

/** Lifecycle */
onMounted(() => {
  isMounted.value = true
})
</script>

<template>
  <UiTabs
    :tabs="colorModeTabs"
    :active-tab="activeTab"
    mode="radio"
    :id-prefix="idPrefix"
    pill-tabs
    size="sm"
    rounded
    fit
    :icon-only="!showLabels"
    aria-label="Color mode"
    @update:active-tab="selectColorMode"
  />
</template>
```

The saved color-mode preference is only known on the client, so the picker renders "System" on the server and follows the preference after mount, which keeps hydration consistent. `mode="radio"` renders a radio group, since the picker controls no panels, and `id-prefix` takes a `useId()` value because `UiTabs` renders each button with the id `<idPrefix>-<id>` and the same picker may also sit in the navbar.

```vue
<script setup lang="ts">
import type { IButtonToggleOption } from '@colorffy/ui'

/** Data */
const densityOptions: IButtonToggleOption[] = [
  { id: 'compact', icon: '&#xeba8;', title: 'Compact', text: 'Tighter spacing' },
  { id: 'comfortable', icon: '&#xeb9e;', title: 'Comfortable', text: 'The default' },
  { id: 'spacious', icon: '&#xeba9;', title: 'Spacious', text: 'More room' }
]
const density = useState<string>('density', () => 'comfortable')

/** Watchers */
watch(density, (mode) => {
  if (!import.meta.client)
    return
  if (mode === 'comfortable')
    document.documentElement.removeAttribute('data-density')
  else
    document.documentElement.setAttribute('data-density', mode)
})
</script>

<template>
  <UiCard variant="pane">
    <template #header>
      <p class="card-title">Interface</p>
      <p class="caption text-muted mb-0">Changes apply right away on this device.</p>
    </template>
    <template #body>
      <div class="row align-items-center">
        <div class="col-12 col-md-5">
          <p class="fw-700 mb-1">Theme</p>
          <p class="caption text-muted mb-3 mb-md-0">Pick a theme or follow your operating system.</p>
        </div>
        <div class="col-12 col-md-7">
          <ColorModePicker />
        </div>
      </div>
      <UiDivider custom-class="my-4" />
      <div class="row align-items-center">
        <div class="col-12 col-md-5">
          <p class="fw-700 mb-1">Density</p>
```

`data-density` on `<html>` retunes spacing and control heights for the whole app (see [density](/colorffy-css/customization#density)); `comfortable` is the default, so it removes the attribute. `useState` keeps the choice across pages but not across a reload; store it in a cookie and apply it from the layout if it should persist.

## Design rules

- Every group is a `UiCard variant="pane"`, and the cards of a panel stack with `d-grid gap-6`.
- A card header is a `.card-title` and one `caption text-muted mb-0` line. A status badge or a header action goes on the right in a `d-flex align-items-start justify-content-between gap-3` wrapper.
- Row titles are `fw-700 mb-1`, hints `caption text-muted`. Matrix cells use `fw-700 fs-xs` so they read as rows, not headings.
- One primary action per card, in the footer and right-aligned. Row-level actions are `text` or `outline` and `size="sm"`.
- Color carries meaning only: `tonal tonal-success` / `tonal tonal-warning` badges for state, a `bg-success-container` callout for a completed setup, `text-danger` and a danger alert for the danger zone.
- Order the tabs from personal to risky (profile, appearance, notifications, security) and put the danger zone last.
- Below `md` every setting row stacks to title, hint, control; the two-column field grid collapses below `sm`, and the notification table scrolls inside `table-responsive`.

## Accessibility

- `UiTabs` renders a `tablist` with arrow-key, Home and End navigation. Each tab sets `panelId`, and each panel is a `<section role="tabpanel">` whose `id` matches it and whose `aria-labelledby` points at `tab-<id>`, the id `UiTabs` gives the tab button.
- Every input has a `label`, including the ones hidden with `hide-label` because the row title shows it. Switches in the notification table carry a label that names both the channel and the event.
- Table headers use `scope="col"`, so each switch is announced with its channel.
- The avatar has `alt` text naming whose photo it is.
- The color-mode picker and the density group carry an `aria-label`; `UiButtonToggleGroup` renders a `radiogroup` of `radio` options.
- The two-factor confirmation is a `role="status"` region, so its appearance is announced.
- Workspace deletion always goes through `UiConfirmModal`; the danger-zone button never deletes on its own.
