The app shell is the Nuxt layout every signed-in page renders inside. It holds the navigation for desktop and phones, the global actions (search, create, notifications, account) and the one toast the pages share.

![Orbit's app shell: sidebar on the left, sticky navbar on top and the account menu open on the right](/recipes/app-shell.jpg)

## Anatomy

1. **Grid**: `grid-main-content` places the sidebar and the main column side by side from 1024px, and stacks them below.
2. **Sidebar**: [UiSidebar](/colorffy-ui/components/sidebar) with a workspace switcher (`UiSidebarDropdown`), links (`UiSidebarLink`), a section label (`UiSidebarText`), a collapsible group (`UiSidebarGroup`), and in the footer a trial card and the user's menu.
3. **Navbar**: [UiNavbar](/colorffy-ui/components/navbar) `sticky fluid` with the sidebar toggle, the page title, a search field ([UiInputSearch](/colorffy-ui/components/inputs)), a create menu ([UiButtonMenu](/colorffy-ui/components/button-menu)), a notifications button and the avatar.
4. **Account menu**: [UiPopoverMenu](/colorffy-ui/components/popover-menu) opened from the avatar, with account links, preferences (including a color mode picker built with [UiTabs](/colorffy-ui/components/tabs)) and sign out.
5. **Notifications**: a [UiPopover](/colorffy-ui/components/popover) anchored to the bell button, listing the latest items in a [UiListGroup](/colorffy-ui/components/list).
6. **Page**: the `<slot />` where each page renders its [page frame](/colorffy-ui/recipes/overview#page-frame).
7. **Mobile bar**: [UiNavigationBar](/colorffy-ui/components/navigation-bar), shown on phones in place of the sidebar.
8. **Toast**: one [UiAlertToast](/colorffy-ui/components/alert) that every page reaches through a composable.

## Page skeleton

```vue [layouts/default.vue]
<script setup lang="ts">
import type { UiAlertToast } from '@colorffy/ui'
import { vOnClickOutside } from '@vueuse/components'
import { NuxtLink } from '#components'

/** Data */
const sidebarCollapse = useState<boolean>('sidebarCollapse', () => false)
const isMenuActive = ref<boolean>(false)
const toastRef = ref<InstanceType<typeof UiAlertToast> | null>(null)
const mobileItems = [
  { id: 'home', to: '/', icon: '&#xe88a;', text: 'Home', ariaLabel: 'Go to home' },
  { id: 'projects', to: '/projects', icon: '&#xe2c7;', text: 'Projects', ariaLabel: 'Go to projects' },
  { id: 'settings', to: '/settings', icon: '&#xe8b8;', text: 'Settings', ariaLabel: 'Go to settings' }

  isMenuActive.value = false

/** Lifecycle */
onMounted(() => register(toastRef.value))
</script>
```

## Drive the sidebar with one boolean

`rail` (the icons-only desktop mode) only applies from 1024px, and `open` (the slide-in drawer) only below it, so one shared state drives both. `useState` keeps it across pages, and `UiNavbarToggle` flips it:

```vue
<template>
  <UiSidebar :rail="sidebarCollapse" :open="sidebarCollapse" @update:open="sidebarCollapse = $event">…</UiSidebar>
  <UiNavbarToggle show-toggle-button :collapsed="sidebarCollapse" @toggle="sidebarCollapse = !sidebarCollapse" />
</template>
```

Give every `UiSidebarLink` a `tooltip-text`. In rail mode the label is hidden and the tooltip names the link.

## Title the navbar from the page

Each page declares its title once with `definePageMeta({ pageTitle: 'Projects' })`, and the layout reads `route.meta.pageTitle`. On a `sticky` navbar, `UiNavbarTitle` fades the title in once the navbar sticks to the top, so the context stays visible after the page header scrolls away without repeating it at the top.

## Add the global actions

The end of the navbar holds the actions that work from any page. A create menu lists what the user can add, with a submenu for less common entries:

Notifications open a native popover anchored to the bell. The button names the popover with `popovertarget` and an `anchor-name`, and `UiPopover` takes the same anchor:


## Put the color mode in the account menu

The account menu closes on a click outside the navbar (`v-on-click-outside` from `@vueuse/components`) and on its own `hide-dropdown` event. `UiPopoverMenuItem as="div"` turns a row into a container, and its `#trailing` slot holds the control. The picker is a small component so the settings page can reuse it:

```vue [components/ColorModePicker.vue]
<script setup lang="ts">
import type { ITabItem } from '@colorffy/ui'

/** Props */
const { showLabels = true } = defineProps<{ showLabels?: boolean }>()

/** Data */
const isMounted = ref<boolean>(false)
const idPrefix = useId()
const colorModeTabs: ITabItem[] = [
  { id: `${idPrefix}-system`, label: 'System', icon: '&#xe31e;' },
  { id: `${idPrefix}-light`, label: 'Light', icon: '&#xe518;' },
  { id: `${idPrefix}-dark`, label: 'Dark', icon: '&#xe51c;' }
]

/** Composables */
const colorMode = useColorMode()

/** Computed */
const activeTab = computed(() => `${idPrefix}-${isMounted.value ? colorMode.preference : 'system'}`)

/** Methods */
function selectColorMode(tabId: string): void {
  colorMode.preference = tabId.slice(idPrefix.length + 1)
}

/** Lifecycle */
onMounted(() => {
  isMounted.value = true
})
</script>

<template>
  <UiTabs
    :tabs="colorModeTabs"
    :active-tab="activeTab"
    pill-tabs
    size="sm"
    rounded
    fit
    :icon-only="!showLabels"
    aria-label="Color mode"
    @update:active-tab="selectColorMode"
  />
</template>
```

The saved preference only exists in the browser, so the server renders "System" and the picker switches to the saved value after mount. That keeps hydration consistent without hiding the control. The `useId()` prefix keeps the tab ids unique when the menu and the settings page both show a picker.

## Share one toast

The layout owns a single `UiAlertToast` and hands it to a composable on mount. Pages call `notify()` and never render their own toast:

```ts [composables/useNotify.ts]
import type { AlertPlacement, AlertVariant, UiAlertToast } from '@colorffy/ui'
import { shallowRef } from 'vue'

const toast = shallowRef<InstanceType<typeof UiAlertToast> | null>(null)

export function useNotify() {
  function register(instance: InstanceType<typeof UiAlertToast> | null): void {
    toast.value = instance
  }

  function notify(title: string, message: string, variant: AlertVariant = 'success', placement: AlertPlacement = 'bottom-right'): void {
    if (!toast.value)
      return
    toast.value.title = title
    toast.value.showToast({ variant, message, placement })
  }

  return { register, notify }
}
```

## Design rules

- The sidebar holds where the user goes; the navbar holds what the user does. Don't repeat a destination in both.
- One filled primary button in the navbar (the create menu). Everything else there is `text` or an avatar.
- Workspace and user switchers are `UiSidebarDropdown` with their menu items in the default slot. Open the header one to the side (`placement="right-start"`) so it doesn't cover the links. `:interactive="false"` turns the dropdown into a static label and drops the items.
- Phones get the `UiNavigationBar` with three to five top-level sections. Its `active-item` is the first path segment, so a detail page still highlights its section.
- A sidebar card (a trial, an announcement) reads the shape and spacing tokens: `border-radius: var(--cffy-shape-container)` and `padding: var(--cffy-space-12)`.

## Accessibility

- The search field keeps its `label` and hides it with `hide-label`.
- Icon-only buttons (notifications) carry an `aria-label`, and each mobile bar item has its own `ariaLabel`.
- The account menu has an `aria-label`, and each `UiPopoverMenuGroup` without a visible heading gets one too (`aria-label="Session"`).
- The color mode tabs form a labelled tablist, and each tab's name stays in the accessibility tree when only icons show.
