The billing screen is where a workspace owner checks what they pay, how close they are to their limits, changes plan and downloads invoices. Use it for any subscription page with a plan, a payment method and a billing history.

![Orbit's billing page: the current plan in a primary card next to usage meters, three plan cards below, then the payment method and the invoice table](/recipes/billing.jpg)

## Anatomy

1. **Header**: [UiHeaderContent](/colorffy-ui/components/layout) with an outline "Download all invoices" [UiButton](/colorffy-ui/components/button) in `#actions`.
2. **Current plan**: a [UiCard](/colorffy-ui/components/card) painted `bg-primary text-on-primary`, the one emphasized surface on the screen, with the plan, the price, a status [UiBadge](/colorffy-ui/components/badge) and the Change plan and Cancel plan buttons.
3. **Usage**: a `UiCard` of labelled meters, one [UiProgressBar](/colorffy-ui/components/progress) per limit, with a tinted hint once a meter passes 80%.
4. **Plans**: a `<section>` with a monthly / yearly [UiButtonToggleGroup](/colorffy-ui/components/button-group#build-a-toggle-group), three `UiCard selectable` options, each with a [UiInputRadio](/colorffy-ui/components/inputs#checkbox-switch-and-radio), a "Most popular" `UiBadge`, a price, a [UiDivider](/colorffy-ui/components/divider) and a feature list, and one button that applies the choice.
5. **Payment method**: a `UiCard` with a [UiAlert](/colorffy-ui/components/alert) when a payment needs attention, the card on file, and the payment processor's logo in a [UiIconSvg](/colorffy-ui/components/icons#custom-svg).
6. **Invoices**: a [UiDatatable](/colorffy-ui/components/datatable) with a date range filter ([UiInputDate](/colorffy-ui/components/inputs#date)), status badges, row selection with a bulk download bar, pagination, and skeleton rows ([UiTableSkeleton](/colorffy-ui/components/skeleton)) while it loads.
7. **Cancel plan**: a [UiConfirmModal](/colorffy-ui/components/modal#uiconfirmmodal) opened from the current plan card.

import type { IButtonToggleOption, IDatatableColumn, IDateRange, UiConfirmModal } from '@colorffy/ui'

import { brandIcons } from '~/utils/brand-icons'

definePageMeta({ pageTitle: 'Billing' })

/** Interfaces */

/** Data */
const usd = new Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD', maximumFractionDigits: 0 })
const usage = [
  { id: 'seats', label: 'Seats', used: 8, limit: 10 },
  { id: 'storage', label: 'Storage (GB)', used: 38, limit: 50 }
].map(meter => ({ ...meter, percent: Math.round((meter.used / meter.limit) * 100) }))
const cycleOptions: IButtonToggleOption[] = [
  { id: 'monthly', title: 'Monthly' },
  { id: 'yearly', title: 'Yearly', badge: { variant: 'tonal tonal-success', text: 'Save 20%' } }
]
const plans = [
  { id: 'free', name: 'Free', monthly: 0, yearly: 0, features: ['3 projects', '1 GB storage'] },
  { id: 'pro', name: 'Pro', monthly: 12, yearly: 10, features: ['Unlimited projects', '50 GB storage'], popular: true },
  { id: 'business', name: 'Business', monthly: 24, yearly: 20, features: ['SAML single sign-on', 'Audit log'] }
]
const columns: IDatatableColumn[] = [
  { key: 'id', label: 'Invoice' },
  { key: 'date', label: 'Date', sortable: false },
  { key: 'amount', label: 'Amount', align: 'end' },
  { key: 'status', label: 'Status' }
]
const invoices: { id: string, date: string, amount: number, status: InvoiceStatus }[] = [
  { id: 'INV-2026-009', date: 'Sep 1, 2026', amount: 96, status: 'paid' },
  { id: 'INV-2026-006', date: 'Jun 1, 2026', amount: 84, status: 'failed' }
]
const statusMeta: Record<InvoiceStatus, { label: string, variant: string }> = {
  paid: { label: 'Paid', variant: 'tonal tonal-success' },
  due: { label: 'Due', variant: 'tonal tonal-warning' },
  failed: { label: 'Failed', variant: 'tonal tonal-danger' }
}
const periodPresets = [datePresets.thisYear(), datePresets.lastMonths(12)]
const cycle = ref('monthly')
const selectedPlanId = ref('pro')
const period = ref<IDateRange | null>(null)
const selectedInvoices = ref<(string | number)[]>([])
const invoicesLoading = ref(true)
const isCanceling = ref(false)
const cancelModal = ref<InstanceType<typeof UiConfirmModal> | null>(null)

/** Computed */
const failedInvoice = computed(() => invoices.find(invoice => invoice.status === 'failed'))
const filteredInvoices = computed(() => {
  const { start, end } = period.value ?? {}
  return start && end ? invoices.filter(invoice => new Date(invoice.date) >= start && new Date(invoice.date) <= end) : invoices
})

/** Methods */
async function cancelPlan(): Promise<void> {
  isCanceling.value = true
  await new Promise(resolve => setTimeout(resolve, 800))
  isCanceling.value = false
  cancelModal.value?.closeDialog()
}

/** Lifecycle */
onMounted(() => setTimeout(() => (invoicesLoading.value = false), 600))
</script>

`brandIcons` is a small local registry of SVG strings (`{ stripe: '<svg …>…</svg>' }`) that the app keeps for the logos it uses. `useNotify()` from the [app shell](/colorffy-ui/recipes/app-shell#share-one-toast) confirms each completed action with a toast.

## Emphasize the current plan

The current plan is the only `bg-primary` surface on the page, so the eye lands on what the workspace pays today before anything else. Put `bg-primary text-on-primary` on the card through `custom-class`, and keep everything inside it in the on-primary color:

- Secondary text (the overline, the unit, the billing cycle) uses `opacity-80`, not `text-muted`, which would switch it to the muted color of the regular surfaces.
- The main action is `variant="filled" color="white"` and the secondary one `variant="frosted"`; both stay readable on any primary color.
- Plan status is a tonal badge in the top corner: days left on a trial, or the end date once the plan is canceled.

```vue
<template>
  <UiBadge v-if="onTrial" :text="`${trialDaysLeft} days left`" variant="tonal tonal-warning" icon-code="&#xe8b5;" />
  <UiBadge v-else-if="isCanceled" text="Ends Oct 15" variant="tonal tonal-danger" icon-code="&#xe14b;" />
</template>
```

Below the price, add the next invoice (date and amount) or, after a cancellation, the date access ends.

## Show usage as labelled meters

Each limit is one row: the name in `fw-600` on the left, "38 of 50 GB" in `caption` on the right, a `size="sm"` progress bar, and the percentage under it. From 80% the bar switches to `bar-class="bg-warning"` and the caption becomes a tinted hint that says what to do next:

```vue
<template>
  <p v-if="meter.percent >= 80" class="d-inline-flex align-items-center gap-1 caption bg-warning-container text-on-warning-container rounded-sm px-2 py-1 mt-2 mb-0">
    <UiIconMaterial icon-code="&#xe002;" class="fs-sm" />
    {{ meter.percent }}% used. Archive old files or upgrade for more space.
  </p>
  <p v-else class="caption text-muted mt-1 mb-0">
    {{ meter.percent }}% used
  </p>
</template>
```

## Pick a plan with selectable cards

Each plan is a `UiCard selectable variant="outline"` nested in the section's pane. The chosen card gets the `selected` class, which holds the primary border; clicking anywhere on the card picks it. The `UiInputRadio` inside makes the same choice reachable with the keyboard and names it for screen readers.

Mark the recommended plan with a `UiBadge` only. A `border` utility on that card would sit above the card's styles and hide the `selected` border, so the popular plan would look the same chosen or not.

The billing cycle toggle drives every price on the page. Its yearly option carries the discount as a badge, and the prices switch to the yearly per-month figure. The button under the cards names what it will do, from the selected plan and cycle against the current ones, and is disabled when they match:

```ts
const planAction = computed(() => {
  const plan = selectedPlan.value
  if (plan.id === currentPlan.value.id && cycle.value === currentCycle.value)
    return { label: `You're on ${plan.name}`, disabled: true }
  if (plan.id === currentPlan.value.id)
    return { label: `Switch to ${cycle.value} billing`, disabled: false }
  if (plan.monthly < currentPlan.value.monthly)
    return { label: `Downgrade to ${plan.name}`, disabled: false }
  return { label: `Upgrade to ${plan.name}`, disabled: false }
})
```

```vue
<template>
  <div class="d-flex flex-wrap justify-content-between align-items-center gap-3 mt-4">
    <p class="caption text-muted mb-0">{{ planSummary }}</p>
    <UiButton :text="planAction.label" :disabled="planAction.disabled" :loading="isUpdatingPlan" variant="filled" color="primary" @click="applyPlan" />
  </div>
</template>
```

`planSummary` spells out the total ("8 seats × $10 = $80 per month, billed yearly at $960"), or, for a downgrade to a plan with fewer seats, who would lose access.

## Flag payment problems on the card

The payment method card opens with a tonal `UiAlert` only while a payment needs action, and the fix sits in its `#actions` slot. A failed charge is `variant="danger"` with Retry payment; a card about to expire is `variant="warning"` with Update card:

```vue
<template>
  <UiAlert type="tonal" variant="warning" title="Your card expires next month" message="Update the Visa ending 4242 before Aug 31 to keep paying without interruption." custom-class="mb-4">
    <template #actions>
      <UiButton text="Update card" variant="filled" color="warning" size="sm" />
    </template>
  </UiAlert>
</template>
```

Wrap the alert in `<Transition name="fade">` so it fades out once the retry succeeds. Logos render through `UiIconSvg :content` from the local registry. Set `:decorative="false"` with an `aria-label` when the logo is the only thing naming the company; the card brand chip is `aria-hidden` because "Visa ending 4242" already says it.

## Filter, select and download invoices

The invoice table puts everything that narrows or acts on the rows in its `#controls` slot:

- **Date range.** `UiInputDate mode="range" trigger="button"` shows "All dates" or the matching preset as a compact button, with `max` set to today. The button trigger has no clear button, so an icon button next to it resets the range while one is set.
- **Bulk bar.** Once rows are selected, the count, a tonal Download and a text Clear replace a hint. `v-model:selected` holds the invoice ids, because `row-key="id"`.
- **Loading.** `is-loading` renders a `UiTableSkeleton` with one cell per visible column, under the real header, so the table doesn't jump when the rows arrive.

```vue
<template>
  <UiButton v-if="period" variant="text" size="sm" icon aria-label="Show invoices from every date" @click="period = null">
    <template #icon>
      <UiIconMaterial icon-code="&#xe5cd;" />
    </template>
  </UiButton>

  <Transition name="fade" mode="out-in">
    <div v-if="selectedInvoices.length" class="d-flex align-items-center gap-2">
      <span class="caption fw-600">{{ selectedInvoices.length }} selected</span>
      <UiButton text="Download" variant="tonal" color="primary" size="sm" @click="downloadSelected" />
      <UiButton text="Clear" variant="text" size="sm" @click="selectedInvoices = []" />
    </div>
    <span v-else class="caption text-muted">Select invoices to download several at once.</span>
  </Transition>
</template>
```

Each row ends with a download button in a column that is `fit`, `hideLabel` and `align: 'end'`:

```vue
<template>
  <UiButtonTooltip variant="text" custom-class="text-neutral" size="sm" icon :tooltip-text="`Download ${item.id}`" @click="downloadInvoice(item.id)">
    <template #icon>
      <UiIconMaterial icon-code="&#xe2c4;" />
    </template>
  </UiButtonTooltip>
</template>
```

On phones the table drops the secondary columns and passes `visibleColumns` to `:columns`. The server renders every column, so the narrow layout waits until the page is mounted (`useMounted` and `useMediaQuery` come from `@vueuse/core`):

```ts
const isMounted = useMounted()
const phoneQuery = useMediaQuery('(width < 600px)')
const isPhone = computed(() => isMounted.value && phoneQuery.value)
const visibleColumns = computed(() => isPhone.value ? columns.filter(column => !['date', 'period', 'plan'].includes(column.key)) : columns)
```

## Confirm before canceling

Cancel plan opens a `UiConfirmModal` whose labels name the plan on both sides ("Cancel Pro" / "Keep Pro"), and whose message says what stops and when. Set `loading-label` to the action in progress, or the button falls back to the generic "Deleting...". The modal stays open while the request runs; close it with `closeDialog()` once it resolves, then confirm with a toast.

## Design rules

- One emphasized surface: the current plan card. Every other region is `UiCard variant="pane"`, and the plan options nested inside a pane are `variant="outline"`.
- The current plan (`col-xl-5`) and usage (`col-xl-7`) share a row with `h-100` on both cards, and stack below 1200px with `gap-block-4` on the row.
- Prices are `fs-3xl fw-800` with the unit beside them in `caption`. Amounts in the table use `tabular-numbers` in an `align: 'end'` column.
- Selection is the `selected` class; recommendation is a badge; status is a tonal `UiBadge` (`success` paid, `warning` due, `danger` failed). Don't use color or borders for any of them on their own.
- One filled action per region: Change plan on the hero (white), the plan button (primary), Retry payment inside the alert (danger). Header and row actions are `outline` or `text`, the bulk download `tonal`.
- Usage turns warning at 80%, and the hint says what to do, not only that the limit is near.
- The invoice table is `data-density="compact"`; the rest of the page keeps the default density.
- Plan changes, retries, card updates and downloads end with a toast; cancellation goes through the confirm modal first.

## Accessibility

- `UiHeaderContent` renders the page's `h1`. The plans region is a `<section>` labelled by its `h2` through `aria-labelledby="plans-title"`.
- Each plan card holds a `UiInputRadio` whose `label` is hidden with `hide-label`, so a plan can be picked with Tab and Space as well as by clicking the card.
- `UiButtonToggleGroup` is a `radiogroup` named by `aria-label="Billing cycle"`; arrow keys, Home and End move the choice.
- Each `UiProgressBar` is a `progressbar` with an `aria-label` naming the limit, and the used / limit text repeats its value.
- Each feature list is a `<ul>` with an `aria-label` naming the plan; the check icons are decorative.
- `UiAlert` renders with `role="alert"`, so a failed payment is announced.
- The card brand chip is `aria-hidden`; the processor logo is an `img` with an `aria-label`.
- The date filter keeps its `label` (hidden with `hide-label`), which becomes part of the button's accessible name. The reset and per-row download buttons are icon-only and named by `aria-label` and `tooltip-text`.
- The table's `caption` is read as its `<caption>`, the pagination has its own `ariaLabel`, and the loading skeleton is a polite `status` region.
- `UiConfirmModal` opens as a modal dialog; its confirm button is disabled while the cancellation runs.
