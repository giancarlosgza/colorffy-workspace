A collection index lists every record of one kind (projects, customers, documents) and is where the user finds, filters and creates them. Use it for the top-level page of a section, with a grid for scanning and a table for comparing.

![Orbit's projects page: header with Export and New project, a search and view toolbar, status filter chips and a three-column grid of project cards](/recipes/collection-index.jpg)

## Anatomy

1. **Header**: [UiHeaderContent](/colorffy-ui/components/layout) with a subtitle that counts the collection, and a [UiButtonGroup](/colorffy-ui/components/button-group) with a secondary action (Export) and the primary one (New project).
2. **Toolbar**: [UiInputSearch](/colorffy-ui/components/inputs#password-search-and-tags), a sort [UiInputSelect](/colorffy-ui/components/inputs#select) and a grid / list switch built with [UiSegmentedControls](/colorffy-ui/components/segmented-controls).
3. **Filters**: a single-select [UiChipGroup](/colorffy-ui/components/chip#single-select-filter-chips) for the status and a standalone [UiChip](/colorffy-ui/components/chip#use-uichip-directly) toggle for "My projects".
4. **Results**, one state at a time inside a fade transition:
   - **Loading**: [UiGridSkeleton](/colorffy-ui/components/skeleton#grid-skeleton) in the grid, the datatable's own skeleton rows in the list.
   - **No results**: [UiEmpty](/colorffy-ui/components/empty) in a [UiCard](/colorffy-ui/components/card), with the action that gets the user out of it.
   - **Grid**: link cards ([UiCard](/colorffy-ui/components/card#make-a-card-a-link)) with a [UiBadge](/colorffy-ui/components/badge), a [UiProgressBar](/colorffy-ui/components/progress) and a [UiAvatarGroup](/colorffy-ui/components/avatar#avatar-group).
   - **List**: [UiDatatable](/colorffy-ui/components/datatable) with custom cells and a [UiButtonMenu](/colorffy-ui/components/button-menu) of row actions.
5. **Create wizard**: [UiModal](/colorffy-ui/components/modal) with a [UiStepper](/colorffy-ui/components/stepper) and one form per step ([UiInputText, UiInputCombobox, UiInputMultiSelect, UiInputDate](/colorffy-ui/components/inputs) and more).
6. **Rename**: a small [UiModal](/colorffy-ui/components/modal) with one field.
7. **Archive**: [UiConfirmModal](/colorffy-ui/components/modal#confirm-a-destructive-action).

])

const step = ref('details')

  const query = search.value.trim().toLowerCase()

/** Methods */
function onStatusChange(value: string | string[] | null) {
  status.value = typeof value === 'string' ? value : 'all'
}
function clearFilters() {
  search.value = ''
  status.value = 'all'
}
function openWizard() {
  draft.name = ''
  step.value = 'details'
  showErrors.value = false
  wizardRef.value?.showDialog()
}
function goNext() {
  showErrors.value = true
  if (draft.name.trim())
    step.value = 'review'
}
function confirmArchive(project: Project) {
  archiveTarget.value = project
  archiveRef.value?.showDialog()
}
function archiveProject() {
  items.value = items.value.filter(project => project.id !== archiveTarget.value?.id)

## Feed both views from one computed

Search, filters and sort run once, in a single `filteredProjects` computed. The grid loops over it, the table reads it, the empty state checks its length and the table's toolbar counts it, so the two views can never disagree about which records match.

```ts
const hasFilters = computed(() => search.value.trim() !== '' || statusFilter.value !== 'all' || onlyMine.value)
const filteredProjects = computed(() => {
  const query = search.value.trim().toLowerCase()
  const list = items.value.filter((project) => {
    const matchesStatus = statusFilter.value === 'all' || project.status === statusFilter.value
    const matchesMine = !onlyMine.value || project.ownerId === currentUser.id || project.memberIds.includes(currentUser.id)
    const matchesQuery = !query || `${project.name} ${project.key} ${project.description}`.toLowerCase().includes(query)
    return matchesStatus && matchesMine && matchesQuery
  })
  return list.sort((a, b) => (sortKey.value === 'name' ? a.name.localeCompare(b.name) : b.progress - a.progress))
})
```

The table needs one more step. `UiDatatable` sorts by the value under each column's `key`, so a column that shows a label but should sort by rank (status, priority) or by date gets a comparable value in a row object built from the same computed. The record itself rides along as `project`, so cell slots still render labels, colors and links from it:

```ts
const tableRows = computed(() => filteredProjects.value.map(project => ({
  id: project.id,
  name: project.name,
  status: STATUS_ORDER.indexOf(project.status),
  progress: project.progress,
  due: dayValue(project.dueDate),
  project
})))
```

```vue
<template>
  <UiDatatable :columns="columns" :items="tableRows" row-key="id" column-manager caption="Projects in the Orbit product workspace">
    <template #controls>
      <span class="caption text-muted">{{ filteredProjects.length }} of {{ items.length }} projects</span>
    </template>
    <template #cell-status="{ item }">
      <UiBadge :text="statusMeta[item.project.status].label" :variant="tonal(statusMeta[item.project.status].color)" size="sm" />
    </template>
  </UiDatatable>
</template>
```

`statusMeta` maps each status to a label, an intent and an icon, and `tonal(color)` turns the intent into a badge variant (`tonal tonal-<color>`). `hasFilters` decides which empty state shows: "No projects match these filters" with an outline **Clear filters** button, or "No projects yet" with the filled **New project** button.

## Filter with chips

The status filter is a single-select `UiChipGroup` with an "All" option. In single mode, clicking the selected chip clears the group to `null`; map that back to `'all'` so one chip always stays selected. Bind `:model-value` and `@update:model-value` instead of `v-model` to do it.

"My projects" is a separate filter, so it is a standalone `UiChip` toggled through `selected`, with `color="secondary"` and a dot between the two to keep it apart from the status set. The sort select sits in the toolbar next to the search:

```vue
<template>
  <div class="d-flex flex-wrap align-items-start gap-2 mb-3">
    <UiInputSearch id="project-search" v-model="search" label="Search projects" hide-label placeholder="Search by name, key or description" class="flex-grow-1 mb-0" />
    <UiInputSelect id="project-sort" v-model="sortKey" label="Sort projects" hide-label :options="sortOptions" option-label="label" option-value="value" class="mb-0" />
    <UiSegmentedControls v-model:active-tab="view" :tabs="viewTabs" />
  </div>

  <div class="d-flex flex-wrap align-items-center gap-2 mb-4">
    <UiChipGroup :options="statusOptions" :model-value="statusFilter" aria-label="Filter by status" @update:model-value="onStatusChange" />
    <span class="text-muted" aria-hidden="true">·</span>
    <UiChip text="My projects" icon-code="&#xe7fd;" color="secondary" :selected="onlyMine" @click="onlyMine = !onlyMine" />
  </div>
</template>
```

Inputs carry a form-group margin; `mb-0` on the toolbar fields and `mb-3` on the row keep the spacing in one place.

## Switch between grid and list

![The same projects page in list view: a datatable with name, owner, status, priority, progress, budget and due columns, and a row action menu open](/recipes/collection-index-list.jpg)

`UiSegmentedControls` writes `'grid'` or `'list'` to `view`. The results are one `v-if` chain inside `<Transition name="fade" mode="out-in">`, so exactly one state renders and swaps with a short fade. The order matters:

1. **Loading in the grid**: `UiGridSkeleton` with the grid's own `grid-layout-classes`, so the placeholders take the cards' place.
2. **No results**: only once loading is over, or an empty first fetch flashes "No projects yet".
3. **Grid**.
4. **List**: also its own loading state, since `UiDatatable` swaps its body for skeleton rows while `is-loading` is set.

Set `isLoading` from your fetch, for example `status.value === 'pending'` from `useFetch`.

## Make each card a link

A project card navigates to the project, so it is a link card: `:as="NuxtLink"` and `:to` render the whole card as one link with hover and press feedback. Don't add `selectable` (that is for choosing a card) and don't put buttons inside a link card; actions on a record live in the list view's menu or on its [detail page](/colorffy-ui/recipes/detail-page).

The card body stacks an identity tile and the status badge, the name with its key, a muted description, and a progress row. A completed project paints its bar with `bar-class="bg-success"`; the footer holds the due date and the team:

```vue
<template>
  <div class="d-flex align-items-start justify-content-between gap-3 mb-3">
    <span class="d-inline-flex p-2 rounded-md" :class="`bg-${project.color}-container text-on-${project.color}-container`">
      <UiIconMaterial :icon-code="project.icon" class="fs-lg lh-1" />
    </span>
    <UiBadge :text="statusMeta[project.status].label" :variant="tonal(statusMeta[project.status].color)" :icon-code="statusMeta[project.status].icon" size="sm" />
  </div>
  <p class="subtitle-1 fw-700 mb-1">
    {{ project.name }}
    <span class="caption text-muted fw-500 ms-1">{{ project.key }}</span>
  </p>
  <p class="subtitle-2 text-muted mb-3">{{ project.description }}</p>
  <UiProgressBar :value="project.progress" size="sm" :aria-label="`${project.name} progress`" :bar-class="project.status === 'completed' ? 'bg-success' : null" />
</template>
```

## Fill the table cells

Each `cell-<key>` slot reuses the grid's vocabulary in a denser form: the name is a `NuxtLink` with a smaller tile (`p-1 rounded-sm`, `fs-sm`), the owner a `UiAvatar size="sm"` next to the name, status and priority `UiBadge size="sm"`, and budget a figure over a `caption text-muted` line. Cells that must not wrap (name, owner, due) take `text-nowrap`, and the progress cell gets its width from the `--cffy-w-fixed` hook on `w-fixed`.

The actions column is a utility column: `hideLabel` keeps its name for screen readers, `hideable: false` keeps it out of the column manager and `fit` sizes it to the button.

## Add row actions

Row actions go in one icon-only `UiButtonMenu` at the end of the row. The menu opens `bottom-end` and the submenu `left-start` so neither runs off the table's right edge. Each trigger gets a unique `id`, and `tooltip-text` names it. A `UiButtonMenuText` repeats which record the menu acts on, and the destructive item comes last, after a divider:

```vue
<template>

</template>
```

## Build the create wizard

The wizard is a `UiModal size="md"` with `:close-on-click-outside="false"`, so a stray click doesn't throw away a half-filled form. A custom `#header` shows "Step 2 of 3" and the step's description under the title, next to a close button. `UiStepper` with `linear` lets the user go back to a finished step but not skip ahead; only **Next** moves forward, and it validates first:

```ts
const nameErrors = computed(() => (showErrors.value && !draft.name.trim() ? ['Give the project a name to continue'] : []))
const dueErrors = computed(() => (draft.start && draft.due && draft.due < draft.start ? ['The due date has to come after the start date'] : []))

function goNext() {
  if (wizardStep.value === 'details' && (!draft.name.trim() || dueErrors.value.length)) {
    showErrors.value = true
    return
  }
  const next = wizardSteps[wizardIndex.value + 1]
  if (next)
    wizardStep.value = next.id
}

watch(wizardIndex, (next, previous) => {
  stepTransition.value = next > previous ? 'slide-start' : 'slide-end'
})
```

A required field only shows its error after the first attempt (`showErrors`); a contradiction such as a due date before the start shows as soon as it exists. The steps sit in `<Transition :name="stepTransition" mode="out-in">`, so they slide forward or back with the direction of travel.

- **Details**: name (`required autofocus`), description, a client `UiInputCombobox` that [searches on the server](/colorffy-ui/components/inputs#search-on-the-server) and accepts `free-text`, labels in a `UiInputMultiSelect` with `free-text` and `:max="5"`, visibility as a `UiInputRadio`, and color, start and due dates in a `row` (`col-12 col-sm-4`, then `col-6 col-sm-4`). The due `UiInputDate` takes `:min="draft.start"`.
- **Team**: a `UiListGroup variant="flush"` with one `UiInputCheck` per member, a lead picked with `UiInputCombobox` from the people just checked, and stakeholders from a remote `UiInputMultiSelect` with `:min-search-length="2"`. A watcher resets the lead to the current user when the lead is unchecked.
- **Review**: a `bg-primary-container` summary of the name and description, then the choices in a two-column `d-grid`, each under an `overline text-muted` label.

```vue
<template>
  <UiInputCombobox id="new-project-lead" v-model="draft.leadId" label="Project lead" placeholder="Search the team" :options="teamMembers" option-label="name" option-value="id" empty-text="Add them to the team first">
    <template #option="{ option }">
      <UiAvatar v-bind="avatarOf(option)" size="sm" />
      <span class="d-flex flex-column">
        <span>{{ option.name }}</span>
        <span class="caption text-muted">{{ option.title }}</span>
      </span>
    </template>
  </UiInputCombobox>
</template>
```

The footer swaps **Cancel** for **Back** after the first step, and **Next** (`icon-trailing` arrow) for **Create project** with `:loading` on the last one.

## Open the wizard from anywhere

The app shell's create menu and the dashboard link to `/projects?new=1`. The page opens the wizard when it sees the flag, on mount and on later navigations, and then drops it from the URL so a reload doesn't reopen it:

```ts
function openFromQuery() {
  if (route.query.new !== '1')
    return
  openWizard()
  const { new: _new, ...query } = route.query
  router.replace({ query })
}

watch(() => route.query.new, openFromQuery)
onMounted(openFromQuery)
```

`openWizard()` resets the draft and the step before `showDialog()`, so every run starts clean.

## Rename and archive

Rename is a `UiModal size="sm"` with one `UiInputText`. **Save** stays disabled while the name is blank, and the field explains why:

```vue
<template>
  <UiModal ref="renameRef" title="Rename project" size="sm">
    <template #body>
      <UiInputText id="rename-project" v-model="renameValue" label="Project name" maxlength="60" :error-messages="renameValue.trim() ? [] : ['A project needs a name']" />
    </template>
    <template #footer>
      <UiButton text="Cancel" variant="text" @click="renameRef?.closeDialog()" />
      <UiButton text="Save" variant="filled" color="primary" :disabled="!renameValue.trim()" @click="saveRename" />
    </template>
  </UiModal>
</template>
```

Archive goes through `UiConfirmModal variant="danger"`. The title names the project, the message says what happens and how to undo it, and the cancel label (**Keep project**) says what cancelling means. `confirm` leaves the dialog open, so set `:is-loading` while the request runs and call `closeDialog()` when it ends. Every completed action (created, renamed, archived, exported) ends in a toast from the [app shell](/colorffy-ui/recipes/app-shell#share-one-toast).

## Design rules

- Results always sit on `UiCard variant="pane"`: the empty state, each grid card and the table. Switching views or states never changes the surface.
- The grid is `d-grid grid-repeat-cols-1 grid-repeat-cols-md-2 grid-repeat-cols-xl-3 gap-3`; pass the same classes to the skeleton. Cards have no fixed width.
- Card type scale: name `subtitle-1 fw-700`, key `caption text-muted fw-500`, description `subtitle-2 text-muted`, meta lines `caption`. Percentages and money take `tabular-numbers`.
- Status is a `UiBadge` with a tonal intent variant. Red text (`text-danger-emphasis fw-600`) marks only an overdue date, next to a badge that already says "Off track".
- The identity tile uses the record's container pair (`bg-<intent>-container text-on-<intent>-container`) so each project keeps its color across the grid, the table and the detail page.
- One filled primary action per region: **New project** in the header, **Next** / **Create project** in the wizard. The empty state's button matches its cause: outline **Clear filters** for no matches, filled **New project** for an empty collection.
- The toolbar wraps: the search takes the free space with `flex-grow-1` and drops above the controls on narrow screens. The table scrolls sideways instead of squeezing columns.

## Accessibility

- The search and sort fields keep their `label` and hide it with `hide-label`.
- The status chips render a `role="group"` named by `aria-label="Filter by status"`.
- `UiSegmentedControls` renders a `tablist` with roving focus, and each tab button gets the id `tab-<id>`. Each tab sets `panelId`, and the results wrapper is a `role="tabpanel"` labelled by the active tab.
- `UiGridSkeleton` and `UiEmpty` are `role="status"` live regions, so loading and "No projects match these filters" are announced as the filters change.
- Every progress bar has an `aria-label` that names its project.
- The table has a `caption`, and sortable headers expose `aria-sort`.
- The row menu trigger is named by `tooltip-text` and follows the menu button keyboard pattern, including → and ← for the submenu.
- The wizard's name field has `autofocus`, so the dialog opens in it. `error-messages` sets `aria-invalid` and links the message with `aria-describedby`. The stepper marks the current step with `aria-current="step"`, and the icon-only close button has an `aria-label`.
