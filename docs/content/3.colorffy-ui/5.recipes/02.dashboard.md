The dashboard is the first page after sign-in. It tells the user what needs attention today, shows a few numbers for the whole workspace, and links into the screens where the work happens.

![Orbit's home dashboard: a greeting header, four KPI cards with the first in the primary color, the My tasks and Projects cards side by side, and the recent activity timeline below](/recipes/dashboard.jpg)

## Anatomy

1. **Greeting**: [UiHeaderContent](/colorffy-ui/components/layout) with the date as `headline`, a greeting as `title` and a one-sentence summary as `subtitle`. The actions are two [UiButton](/colorffy-ui/components/button)s in a [UiButtonGroup](/colorffy-ui/components/button-group).
2. **KPI row**: four [UiCard](/colorffy-ui/components/card)s in a `row`. The first is the emphasized one; the others pair a label with an icon chip ([UiIconMaterial](/colorffy-ui/components/icons)) and, when the metric needs a definition, an info button in a [UiTooltip](/colorffy-ui/components/tooltip).
3. **My tasks**: a card with a [UiSubheadingContent](/colorffy-ui/components/layout) header, [UiTabs](/colorffy-ui/components/tabs) with count badges, and a [UiListGroup](/colorffy-ui/components/list) of rows that each start with a [UiInputCheck](/colorffy-ui/components/inputs) and end with a due date and a [UiBadge](/colorffy-ui/components/badge).
4. **Projects**: a card listing the active projects, each with a status badge, a [UiProgressBar](/colorffy-ui/components/progress) and a [UiAvatarGroup](/colorffy-ui/components/avatar) of its members.
5. **Recent activity**: a full-width card with a [UiTimeline](/colorffy-ui/components/timeline), replaced by [UiBaseSkeleton](/colorffy-ui/components/skeleton) rows while it loads.
6. **Quick create**: a [UiButtonFabGroup](/colorffy-ui/components/button-group) that takes over the header actions on phones.

## Write the greeting

The header speaks to one person. `headline` holds the date (it renders as a small `caption text-primary` eyebrow), `title` the greeting, and `subtitle` a sentence built from the user's own tasks, so it changes with the data instead of repeating the KPI cards:

```ts
/** Computed */
const summary = computed(() => {
  const today = dueTodayCount.value
  const late = overdueTasks.value.length
  const todayLabel = `${today} ${today === 1 ? 'task' : 'tasks'}`

  if (today && late)
    return `You have ${todayLabel} due today and ${late} overdue.`
  if (today)
    return `You have ${todayLabel} due today.`
  if (late)
    return `Nothing due today, but ${late} ${late === 1 ? 'task is' : 'tasks are'} overdue.`
  return 'Your day is clear. Nice work.'
})
```

`size="md"` sets the title one step above the `sm` default of list pages, which marks the home page without a hero. `hide-actions-when-narrow` drops the actions once the header's container is 700px or narrower, instead of wrapping them under the subtitle; the [quick-create FAB](#add-a-quick-create-fab) covers them there.

## Lead with one emphasized KPI

The first card is the user's own number, so it is the only one in the primary color: `bg-primary` on the card through `custom-class`, and `text-on-primary` on a wrapper inside `#body`. Its icon chip uses the `bg-primary-container text-on-primary-container` pair so it stays visible on the filled surface, and the note fades with `opacity-80` instead of switching to `text-muted`, which would lose contrast on primary.

The other cards stay on the pane surface. Each reads top to bottom as label (`caption fw-600 text-muted`), value (`fs-3xl fw-800 lh-1 tabular-numbers`) and one note line (`caption text-truncate`). The icon chip on the right is `UiIconMaterial` with `icon-wrap icon-wrap-xs` and the intent's container pair, built from the stat's `color`. A note that reports a change can take an emphasis color (`text-success-emphasis fw-600`); everything else stays `text-muted`.

When a label needs a definition, such as which projects count as at risk, put a compact info button next to it inside a `UiTooltip`, rather than a longer label: a `text` button with `icon icon-variant="compact-sm" size="sm"` and `custom-class="text-neutral"`, so it sits at caption size and doesn't read as an action.

`col-6 col-xl-3` puts the cards two by two below 1200px and in one row above it. `custom-class="h-100"` keeps them the same height when a note wraps or a tooltip button makes one label taller.

## Filter tasks with tabs

The tabs filter one list, so they all point at one panel: every tab item has the same `panelId`, and the panel's `aria-labelledby` follows the active tab. Each tab carries its count as a pill badge, and a tab with nothing in it drops the badge instead of showing a zero:

```ts
/** Computed */
const taskTabs = computed<ITabItem[]>(() => [
  { id: 'upcoming', label: 'Upcoming', panelId: 'my-tasks-panel', badge: countBadge(upcomingTasks.value.length, 'tonal tonal-primary') },
  { id: 'overdue', label: 'Overdue', panelId: 'my-tasks-panel', badge: countBadge(overdueTasks.value.length, 'danger') },
  { id: 'completed', label: 'Completed', panelId: 'my-tasks-panel', badge: countBadge(completedTasks.value.length, 'tonal tonal-success') }
])

/** Methods */
function countBadge(count: number, variant: string): ITabItem['badge'] {
  return count ? { text: String(count), variant, pill: true } : null
}
```

Only the Overdue count uses a filled `danger` badge; the others are tonal, so the one count that needs action stands out.

Each row is a `UiListItem` with `has-actions`. The `#media` slot holds the checkbox in place of an icon, labelled with the task title and hidden with `hide-label`, so the row's title stays the visible text. The `#list-action` slot holds the due date and a priority badge. The due date takes `text-warning-emphasis fw-600` when it is today and `text-danger-emphasis fw-700` when it is overdue, on top of the date itself and the Overdue tab.

When a box is checked, update the task and confirm with the app shell's [shared toast](/colorffy-ui/recipes/app-shell#share-one-toast) rather than a message in the card. Bind it with `@update:model-value="toggleTask(task, $event)"`:

```ts
/** Composables */
const { notify } = useNotify()

/** Methods */
function toggleTask(task: Task, checked: string | boolean | null) {
  task.done = Boolean(checked)
  if (checked)
    notify('Task completed', `"${task.title}" moved to Completed.`, 'success')
  else
    notify('Task reopened', `"${task.title}" is back on your list.`, 'info')
}
```

Animate the switch between tabs with a `fade` transition around the list and its empty message, and the rows with a `list` transition group, so a checked task slides out of Upcoming instead of disappearing:

```vue
<template>
  <Transition name="fade" mode="out-in">
    <UiListGroup v-if="visibleTasks.length" variant="flush">
      <TransitionGroup name="list">
        <UiListItem v-for="task in visibleTasks" :key="task.id" :title="task.title" :text="task.project" has-actions>
          <!-- Check and actions -->
        </UiListItem>
      </TransitionGroup>
    </UiListGroup>

    <p v-else class="subtitle-2 text-muted text-center py-5 mb-0">
      {{ emptyTaskMessage }}
    </p>
  </Transition>
</template>
```

Give each tab its own empty sentence ("Nothing overdue. You are ahead of schedule."), not one generic line.

## Show project progress

Each project row has two lines. The first holds the name (a link to the project) over a `caption text-muted` line with the due date and task count, and a status badge at the end. The second holds the progress bar, its percentage and the members. Rows after the first are separated with `border border-top` and `pt-3`, and every row but the last gets `pb-3`.

The bar keeps the primary color while a project is on track. `bar-class` switches it to `bg-warning` for at risk and `bg-danger` for off track, matching the status badge next to it. The members are a `UiAvatarGroup` capped at three, inside a `UiTooltip` that lists every name, since the `+N` avatar hides the rest:

```vue
<template>
  <div class="d-flex align-items-center gap-3">
    <UiProgressBar :value="project.progress" :bar-class="project.barClass" :aria-label="`${project.name} progress`" size="sm" class="flex-grow-1" />
    <span class="caption fw-600 tabular-numbers">{{ project.progress }}%</span>
    <UiTooltip :text="project.members.map(member => member.alt).join(', ')">
      <UiAvatarGroup :avatars="project.members" :max="3" size="sm" />
    </UiTooltip>
  </div>
</template>
```

`project.members` is an `IAvatarProps[]`: `{ src, alt }` for a photo, or `{ initials, alt, color }` for a member without one. Show the active projects only, and no more than four; the "All projects" link covers the rest.

## Load the activity feed

While the feed loads, the card shows skeleton rows in the shape of the timeline: a round `thumbnail` skeleton for the marker and one or two text bars of different widths. The wrapper is the single `role="status"` region with its own `aria-label`, and each `UiBaseSkeleton` is silenced with an empty `role` and `ariaLabel` and `ariaLive: 'off'`, so a screen reader announces one loading state, not one per bar. A `fade` transition with `mode="out-in"` swaps the skeleton for the timeline.

With real data, derive the loading flag from the request instead of a timer. Fetching on the client only keeps the rest of the page from waiting on the feed:

```ts
/** Composables */
const { data: activity, status } = useLazyFetch<ITimelineItem[]>('/api/activity', { server: false, default: () => [] })

/** Computed */
const activityLoading = computed(() => status.value === 'idle' || status.value === 'pending')
```

The `#item` slot replaces the timeline's default title, text and time stack, so the time sits at the end of the row and the sentence can bold its actor and target. `ITimelineItem` only carries the marker, the time and the text fields, so keep the sentence parts in a record keyed by the item `id`:

```vue
<template>
  <UiTimeline :items="activity">
    <template #item="{ item }">
      <div class="d-flex align-items-start justify-content-between gap-3">
        <p class="mb-0">
          <span class="fw-700">{{ entries[item.id]?.actor }}</span>
          {{ entries[item.id]?.action }}
          <span class="fw-600">{{ entries[item.id]?.target }}</span>
        </p>
        <span class="caption text-muted text-nowrap">{{ item.time }}</span>
      </div>
    </template>
  </UiTimeline>
</template>
```

Color each marker with the item's `variant`, using the same intent as the event (`success` for completed, `danger` for a project flagged off track).

## Add a quick-create FAB

On phones the header actions are hidden, so a floating button takes over. `custom-class="btn-fab fab-mobile"` on a `UiButton` inside `UiButtonFabGroup` makes it a FAB that only shows below 768px, with its label hidden below 1024px so it renders as a round icon button.

The main FAB toggles a short list of create actions. `fabActions` returns the actions only while the menu is open, and the `slide-up` transition group animates them in and out. The main button's icon switches to a close icon, its `aria-label` to "Close quick create", and `aria-expanded` follows the state. Each action is a link (`:as="NuxtLink"`) that closes the menu on click; an action that creates something in place, like a draft task, calls a method instead.

## Design rules

- Order the regions by how personal they are: the user's summary, the KPIs, the user's tasks, the team's projects, then the feed.
- One emphasized KPI card (`bg-primary`), and it is the user's own number. The other KPIs carry their intent only in the icon chip.
- KPI values use `fs-3xl fw-800 lh-1 tabular-numbers`; percentages and counts elsewhere on the page also take `tabular-numbers`, so they don't shift as they update.
- Below the KPIs the page splits 7/5 from 992px (`col-lg-7`, `col-lg-5`), with `custom-class="h-100"` on both cards, and the activity feed runs full width underneath.
- Every card header is `UiSubheadingContent as="h2" gutter="none"` with at most one `text` button that links to the full screen ("All tasks", "Open inbox").
- The header has one filled primary action (New task) and one outline action (Invite), both `size="sm"`. The cards only have `text` buttons.
- Status reads from badges and progress bar colors. Due-date colors add emphasis to text that already says the date, never replace it.
- Keep each list short (a handful of tasks, four projects, the latest activity) and link to the full screen; the dashboard is not where the user manages records.

## Accessibility

- The page title is the header's `h1`; the card titles are `h2` (`as="h2"`), so the page outline is greeting, then one heading per card.
- The task tabs set `panelId` on every item, which `UiTabs` renders as `aria-controls`; the shared panel is `role="tabpanel"` with `aria-labelledby="tab-<id>"`, the id `UiTabs` gives each tab button.
- Each task checkbox has a unique `id` and the task title as its `label`, visually hidden with `hide-label`.
- The KPI info button has an `aria-label` ("About at-risk projects"); the tooltip opens on hover and keyboard focus.
- Each progress bar has an `aria-label` naming its project.
- The activity skeleton is one `role="status"` region named "Loading recent activity"; the individual skeleton bars are silent.
- The FAB names its state with `aria-label` and `aria-expanded`, and each action keeps an `aria-label` because its visible label is hidden on phones.
- Checking or unchecking a task is confirmed through the shared toast, not an alert that stays on the page.
