A recipe is a complete screen assembled from Colorffy UI components and Colorffy CSS utilities: a dashboard, a list with filters, a settings page. Each one comes from Orbit, the project-management app in the repository's Nuxt playground (`playground/nuxt`), and none of them needs page-level CSS.

Every recipe page has a screenshot, the anatomy of the screen, a page skeleton you can paste and fill with your data, and the rules that keep it consistent with the others.

| Recipe | Use it for |
|---|---|
| [App shell](/colorffy-ui/recipes/app-shell) | The frame around every page: sidebar, navbar, account menu, mobile bar, toasts |
| [Dashboard](/colorffy-ui/recipes/dashboard) | A home screen with KPIs, a task list, progress and recent activity |
| [Collection index](/colorffy-ui/recipes/collection-index) | Browsing, filtering and creating records in a grid or a table |
| [Detail page](/colorffy-ui/recipes/detail-page) | One record with a breadcrumb, properties and tabbed sections |
| [Settings](/colorffy-ui/recipes/settings) | Tabbed preferences grouped into cards of label and control rows |
| [Billing](/colorffy-ui/recipes/billing) | Current plan, usage, plan picker, payment method and invoices |

## Set up the app

The recipes use Nuxt with the `@colorffy/ui/nuxt` module, so every `Ui*` component is auto-imported. Colorffy CSS switches to dark mode on `html.dark-mode`, which `@nuxtjs/color-mode` produces with `classSuffix: '-mode'`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  css: ['@colorffy/css'],
  modules: ['@nuxtjs/color-mode', '@colorffy/ui/nuxt'],
  colorMode: { preference: 'system', classSuffix: '-mode' },
  experimental: { viewTransition: true }
})
```

In a Vue app without Nuxt, register the components with `app.use(ColorffyUI)`, replace `NuxtLink` with `RouterLink` and toggle the `dark-mode` class yourself.

## Page frame

Every page inside the [app shell](/colorffy-ui/recipes/app-shell) starts the same way: a `container` with a little space above and more below, then a `UiHeaderContent`. The page title also feeds the navbar through `definePageMeta`:

```vue [pages/projects/index.vue]
<script setup lang="ts">
definePageMeta({ pageTitle: 'Projects' })
</script>

<template>
  <div class="container mt-3 mb-5">
    <UiHeaderContent title="Projects" subtitle="6 active · 1 in planning" view-transition-name="page-title">
      <template #actions>
        <UiButton text="New project" variant="filled" color="primary" size="sm" />
      </template>
    </UiHeaderContent>

    <!-- Content -->
  </div>
</template>
```

Use `container-fluid` only for screens that split into panes, such as a list next to its detail. `view-transition-name="page-title"` lets the title morph between pages when view transitions are on.

## Design rules

These rules hold across every recipe. The recipe pages add the rules specific to their screen.

### Surfaces

- Group content in `UiCard variant="pane"`. Use one surface style per app.
- Cards in the same row get `custom-class="h-100"` so they share a height.
- A card header is a `.card-title` followed by one `caption text-muted mb-0` line that says what the card is for.
- Use `UiCard variant="outline"` only for content nested inside a pane, such as a preview or a selectable option.

### Layout and spacing

- Use `row` and `col-*` for grids, with `mb-3` on each column, and `d-grid gap-6` to stack the cards of one section.
- Put `gap-block-*` on a `row` whose columns wrap, instead of margins on each column.
- Inside a card, lay out with `d-flex` and `gap-2` (related items) or `gap-3` (separate items), never fixed widths. When a cell needs a width, set the `--cffy-w-fixed` hook on `w-fixed`.
- In custom CSS, read `--cffy-space-*` for spacing and the shape roles (`--cffy-shape-container`, `-field`, `-control`) for corners, so density modes and theme presets reach it.

### Typography

- Metrics: `fs-3xl fw-800 lh-1 tabular-numbers`.
- Meta text (dates, counts, hints): `caption text-muted`.
- A label above a value or a control: `fw-700 mb-1`, or `fw-600` when it sits inside a list row.
- Headings inside a card body: `UiSubheadingContent as="h2"` with `gutter="none"`.

### Color and emphasis

- One emphasized surface per screen at most: `bg-primary` on the card plus `text-on-primary` on its content (the main KPI, the current plan).
- Tinted callouts use the container pair: `bg-<intent>-container text-on-<intent>-container rounded-md p-3`.
- Icon chips use `UiIconMaterial` with `icon-wrap icon-wrap-xs` and the same container pair.
- Status uses `UiBadge` with an intent variant (`tonal tonal-success`, `warning`, `danger`). Never color plain text to carry status.

### Actions

- One primary action per region: `variant="filled" color="primary"`. Secondary actions are `outline`, tertiary ones `text`.
- Header actions are `size="sm"` and sit in a `UiButtonGroup` in the `#actions` slot.
- Icon-only buttons are `UiButtonTooltip` with an `aria-label`; the tooltip shows the same text.
- Anything destructive or hard to undo goes through `UiConfirmModal`.
- Row actions go in a `UiButtonMenu` at the end of the row, not in a row of buttons.

### States

- Every collection has three states besides the data: loading (a skeleton the size of the content), empty (`UiEmpty` with the action that fills it) and no results (`UiEmpty` with a way to reset the filters).
- Confirm completed actions with a toast, not an alert that stays on the page.
- Async results live in a region with `aria-live="polite"`.

### Motion

Pair state changes with Vue's `<Transition>` and `<TransitionGroup>` and the transition names Colorffy CSS ships. They read the duration and easing tokens, and under `prefers-reduced-motion: reduce` they keep the fade and drop the movement, so the recipes need no motion CSS of their own.

| When | Use |
|---|---|
| One state replaces another: loading, content, empty, no results; tab panels; grid and list views | `<Transition name="fade" mode="out-in">` around a `v-if` / `v-else-if` chain |
| Rows are added, removed or reordered in a list | `<TransitionGroup name="list">`; the remaining rows slide into place |
| A wizard moves between steps | `slide-start` going forward, `slide-end` going back; both flip in right-to-left layouts |
| A bar or message appears below the content it belongs to, such as a bulk-action bar or an inline alert | `<Transition name="slide-up">` |
| A panel appears in place, such as an inline confirmation | `<Transition name="scale">` |
| The user moves to another page | A view transition: `experimental.viewTransition` plus `view-transition-name` on the page header |

```vue
<template>
  <Transition name="fade" mode="out-in">
    <UiGridSkeleton v-if="isLoading" key="loading" :skeleton-grid-items="6" />
    <UiEmpty v-else-if="!projects.length" key="empty" title="No projects yet" />
    <div v-else key="grid" class="row">
      <div v-for="project in projects" :key="project.id" class="col-12 col-md-6 col-xl-4 mb-3">
        <UiCard variant="pane" :title="project.name" />
      </div>
    </div>
  </Transition>
</template>
```

- Use `mode="out-in"` whenever one state replaces another, so the old and the new never stack and the layout doesn't jump.
- Give each branch its own `key`, and keep one root element per branch.
- Animate what changed, not the whole page: wrap the region that swaps, not the card around it.
- Don't add a transition to the first render; content that is already there when the page opens just appears.
- Use Nuxt's `page` and `layout` transitions or view transitions between pages, not both.
- Tune the motion with the `--cffy-transition-*` hooks or `--cffy-duration-unit`, not with per-component CSS. See [Transitions](/colorffy-css/utilities/effects#transitions).

### Accessibility

- Every input has a `label`. Hide it with `hide-label` when the layout shows it some other way; never leave it out.
- Tabs that switch page sections set `panelId` on each tab, and each section is `role="tabpanel"` with `aria-labelledby="tab-<id>"`: `UiTabs` renders each tab button with the id `tab-<id>`.
- Progress bars, icon buttons and groups of controls get an `aria-label` that names what they measure or do.

### Responsive and density

- Phones get a `UiNavigationBar` in place of the sidebar. Header actions can hide with `hide-actions-when-narrow` when the page has another way to reach them.
- Brand panels and secondary columns hide below their breakpoint with `d-none d-lg-flex` or `d-none d-xl-block`.
- Dense data tables take `data-density="compact"`; touch screens keep full-size controls inside it.
- Let the user pick the density for the whole app with `data-density` on `<html>`, as the [settings recipe](/colorffy-ui/recipes/settings) does.

## Theme the recipes

The recipes read only tokens, so a theme preset restyles all of them at once: the brand color tints the surfaces, buttons and charts, and the shape roles round every card, field and button. Orbit ships six presets (Orbit, Luxury, Playful, Enterprise, Wellness and Studio); copy their CSS from [Theme presets](/colorffy-css/customization#theme-presets) and switch them with `data-theme` on `<html>`.
